# 会话内容搜索验收

日期：2026-10-13。范围仅为用户选定的第 1 项：跨会话正文搜索、命中摘录、确切消息定位及按需读取上下文。本轮不调整模型、Rerank、回答质量或文档任务租约；无新增迁移。

## 功能与合同

- 会话侧栏新增「搜索会话内容」，查找本人所有活跃及归档会话中的提问和全部回答版本，不受侧栏知识库筛选影响。输入支持防抖、中文组合输入及取消旧请求；结果显示标题、角色、时间、归档状态和纯文本高亮摘录。
- `GET /api/v1/chat/messages/search` 接收 `q`、可选 `sessionId`、`page/pageSize`。不区分大小写的字面子串匹配，`%/_/!` 不作为 SQL 通配符。计数和结果均排除他人会话、软删除会话及任一不可访问的知识库依赖。正式合同见 [API 设计](04-api-design.md#get-chatmessagessearch) 中的同名接口。
- 点击命中直接使用 `around=<messageId>&limit=50` 读取目标附近历史，保留窗口两端完整问题/回答版本组。支持向前/向后继续加载及「回到最新消息」，旧版本会自动选中。同会话草稿保持；后方仍有未读历史时暂停发送和最新回答重生成。
- 完整小会话沿用本地查找，部分历史使用服务端分页查找；上一条/下一条可跨结果页。导出及跨刷新未知写操作对账仍读取完整证据。
- 目标消息已删除返回 `CHAT_MESSAGE_NOT_FOUND`，显示局部提示；初始深链回退到最近页，继续翻页和重试不会重复定位失效消息。其他 403/404 清空会话和来源并返回新对话。

## 真实 API 与浏览器

验收在 `rag_accept_20261013_chat_search` 执行全部 34 个 SQL 文件（001–033，含两个 010），建立合成用户、三份知识库、1002 条长会话历史、三个回答版本、归档会话及他人会话。API 监听 18084，生产前端预览监听 15177，不启动测试 worker，不调用外部模型。浏览器统一为 1920×1080。

| 场景 | 实测结果 |
| --- | --- |
| 搜索与权限 | 活跃及归档均命中；Unicode 和 SQL 特殊符号按字面匹配；纯文本摘录有界，结果翻页稳定；他人会话不可见。 |
| 指定历史窗口 | 1002 条历史中返回 50 条上下文，包含目标及全部回答版本；双向续页连续，无重复/缺失；旧 revision 冲突和跨会话游标被拒绝。 |
| 浏览器定位 | 搜索旧回答自动显示第 1/3 版，目标可见并聚焦；首次只请求 `around`，显示 48 个消息块、1434 个 DOM 元素，没有页面横向溢出。明暗主题截图已检查。 |
| 长会话查找 | 499 条匹配支持上一条循环到第 499 条，读取结果第 25 页；前后上下文与回到最新可用，同会话草稿保持；该流程未请求全量历史。 |
| 归档会话 | 搜索命中进入确切消息，侧栏同步为已归档。 |
| 失效链接 | 404 消息缺失提示保留会话，回退最近 50 条；继续向前读取后显示 100 条，不再次请求失效目标。离线重试原方向由前端回归覆盖。 |
| 撤销附加库权限 | 下一次历史读取返回 404，已显示的消息清空并返回 `/chat`；直接打开撤权深链同样清理；全局搜索只剩仍可访问的归档命中。 |
| 完整性 | 全量导出包含完整历史；API 仍兼容无分页参数读取。控制台仅出现验收预期的消息不存在/撤权 404，无额外脚本错误或警告。 |

单次远端上下文请求为 **2124.8ms**，包含远端 PostgreSQL 与鉴权等待；此结果只证明读取数量受控，不宣称响应延迟降低。按组扩展可能超过 50 条；连续手动翻页仍累积已加载消息，未实现虚拟列表。搜索没有专用全文索引，未对更大数据量、并发写入或通用语言排序规则做性能基准。
