# 前端质量与性能改进计划

制定日期：2026-09-24。实施更新：2026-10-08。状态：F1–F6 已实施并完成本地验证，后续补齐长会话开始与结束阶段的重复解析优化。本计划基于任务开始时的工作区复核；下文保留阶段设计，实际结果和验证限制见末尾。

本计划使用 F1–F6 标识阶段，避免与 [功能优化计划](17-improvement-plan.md) 的 P1–P6 混淆。每阶段独立交付、验证并更新 [当前交接](12-handoff.md)，稳定行为写入 [前端规范](10-frontend-spec.md)；执行边界遵循 [开发规范](00-ai-development-guide.md)。

## 目标与范围

1. 修复已确认的搜索参数丢失、过期响应覆盖和限流提示不更新问题。
2. 减少文档搜索请求与聊天流式期间的重复渲染，并用可复现样本验证效果。
3. 建立产品错误页、静态检查和测试类型检查，逐步统一可共享的服务端数据读取。
4. 降低会话状态维护成本，补齐聊天抽屉和响应式表格的可访问性。

本轮没有证据支持 P0 定级。优先处理影响正确性的问题，再推进性能和结构调整。默认不改后端接口、数据库、RAG 规则或认证机制；新增统计接口另列条件项。现有未提交变更是复核基线，实施时不得通过覆盖或回退这些变更来获得绿色测试。

## 复核结论与取舍

| 原建议 | 核实结果与计划处理 |
| --- | --- |
| 聊天流式渲染整体为 O(n²) | 每次 delta 更新页面状态、重复渲染历史消息成立；当前回答的累计全量 Markdown 解析可能接近平方增长。先测量，再做 F3，不以 JSX 行数推断耗时。 |
| `apiRequest<void>` 遇到 200 + body 会失败 | 200 + 合法 JSON 可正常解析；200 + 空响应或非法 JSON 才会失败。现有删除接口使用 204，不作为紧急修复。 |
| 登录和聊天 429 倒计时不会更新 | 成立，纳入 F1；当前按钮并未因限流倒计时锁定，动态提示与禁用策略分开处理。 |
| 多页面重复请求、数据 hook 重复 | 成立；优先统一知识库选项读取，不将所有本地 state、SSE 和结果对账迁入查询缓存。 |
| 文档和知识库列表均逐字请求 | 文档页成立；知识库列表通过表单提交搜索，没有逐字请求，不改其触发方式。 |
| processing 差值计算语义错误 | 当前六种文档状态下集合等价；风险来自多请求观察到不同时间的数据。聚合统计列为后续条件项。 |
| 无 ErrorBoundary 必然白屏 | React Router 已有默认边界；缺少产品错误页和局部恢复。ESLint 与测试类型检查缺失成立，纳入 F2。 |
| 窄屏归档、删除完全不可达 | 当前顶栏菜单和会话列表菜单仍有入口，不按缺失功能重做；抽屉焦点管理与表格字段标签纳入 F6。 |
| 无引用回答没有兜底 | 已有 `answerStatusNotice`；普通会话回答允许空 citations。只澄清规范，不统一插入“无依据”。 |
| `withQuery` 丢弃 `all` 只是未来风险 | 已会吞掉搜索词 `q=all`，纳入 F1。 |
| 需要新建行尾规则 | 已有 `.gitattributes`；抽查索引为 LF、工作区存在混合行尾。仅维护所改文件，不做全仓归一化。 |

## F1：正确性与请求治理

### 实施内容

1. **参数序列化。** `withQuery` 只做通用序列化，不按字符串值全局删除 `all`。在知识库 `scope`、`visibility` 等确实将 `all` 作为“全部”的资源函数中做字段级归一化，逐个核对现有调用方。保留数字 0、布尔 false、数组和 URL 编码语义。
2. **用户列表竞态。** 为 `UsersPage` 的读取建立请求版本保护，只有最新请求能写入 items、total、loading 和 error。覆盖查询、筛选、分页、刷新和写后刷新；组件卸载失效旧请求。可同时接入 AbortSignal，但不能依赖取消来替代结果版本校验。
3. **文档与用户搜索防抖。** 输入值即时更新，提交到查询的文本默认延迟 250ms；输入法组合期间不触发中间查询。清空、Enter、状态筛选和分页按明确操作立即生效，避免 Enter 后定时器再次发送同一查询。查询变化时重置页码，URL、浏览器前进后退与输入框保持一致；沿用文档页现有取消和版本守卫。知识库列表继续采用表单提交。
4. **429 动态提示。** 保留 `retryAfterSeconds`，接收错误时计算截止时间，由 `Date.now()` 推导剩余秒数；后台恢复可直接校准。归零后移除过期等待文案，不自动重发请求；缺少合法秒数时使用“请稍后再试”。本阶段保留手动重试能力，不增加倒计时禁用按钮。聊天继续恢复被拒问题、编辑时清除旧提示、避免失败回答和 Toast；登录保留表单错误反馈。首次错误可告警，逐秒数字变化不使用 assertive 播报。

主要入口：`frontend/src/api/resources.ts`、`api/client.ts`、`pages/Admin/UsersPage.tsx`、`pages/Documents/useDocumentList.ts`、`DocumentsPage.tsx`、`pages/Login/LoginPage.tsx`、`pages/Chat/useChatThread.ts`、`ChatComposer.tsx`。共享计时逻辑放入专用 hook，命名与最终职责一致。

### 验收与验证

- `q=all` 能传到文档、用户、知识库和全局搜索接口；枚举“全部”仍遵守各接口原有合同。
- 人为让旧请求晚于新请求成功或失败，旧结果均不能覆盖当前用户列表；分页与写后刷新使用当前筛选。
- 稳定挂载后，250ms 内连续输入只提交最终查询一次；文档该次查询最多一组列表与三个 counts 请求，旧请求不能覆盖结果。验证清空、Enter、中文输入法、前进后退和翻页。
- 使用假时钟验证 429 剩余秒数减少、时间跳跃校准、到期、缺失秒数、再次收到 429、编辑清除和卸载清理；验证失败问题恢复与原有重试行为。
- 同步前端规范的搜索触发和限流提示；不改服务器限流规则。

## F2：错误恢复与工程化检查

### 实施内容

1. **产品错误页。** 根路由提供兜底，页面层提供可恢复的错误界面，尽可能保留应用导航；高风险的 Markdown/PDF 渲染可增加局部边界。渲染异常与 API 请求错误分开处理，边界不承担异步事件处理的错误捕获。
2. **明确恢复动作。** 页面渲染失败支持重试或返回；懒加载 chunk 失败提供刷新页面入口，不能假定重置边界即可清除 `React.lazy` 的失败缓存。避免无限自动刷新和展示原始堆栈。整页刷新前说明未保存输入可能丢失。
3. **ESLint。** 使用兼容现有 TypeScript/React 的配置，启用 Hooks 规则；新增 `lint` 脚本与 CI 步骤。清理失效的 eslint 注释，逐项处理依赖问题，不能为了通过检查机械添加依赖或全局关闭规则。优先行为检查，不捆绑格式化全仓。
4. **测试类型检查。** 增加独立测试 tsconfig 和 `typecheck:test` 脚本，覆盖测试文件、辅助 fixture 与测试 setup，明确 Vitest/DOM 类型。接入 CI，保留现有生产构建和路由分包检查；测试无需混入生产产物。
5. **规范一致性。** 将“无引用一律无依据”的旧表述改为按 `answerStatus` 展示：正常会话允许空引用，`no_basis`、检索失败、模型拒答与未知历史状态沿用现有区分。

主要入口：`frontend/src/router/index.tsx`、`src/App.tsx`、`package.json`、`tsconfig*.json`、拟新增 ESLint 配置与错误展示组件、`.github/workflows/ci.yml`、`docs/10-frontend-spec.md`。

### 验收与验证

- 注入子组件渲染异常与 lazy import 拒绝，显示中文恢复界面；相应操作可恢复或刷新，切换正常路由不持续显示旧错误。
- 局部预览异常不会移除聊天正文和输入区；异步请求失败仍走原有可操作提示。
- `npm run lint`、`npm run typecheck:test`、受影响测试和 `npm run build` 通过；CI 使用同一检查入口。
- 修复 lint 发现的行为问题时补相关行为验证，不将“lint 通过”等同于运行正确。

## F3：聊天流式渲染优化

### 测量基线

使用本地固定消息 fixture 与可控 SSE 替身，不调用真实模型。保存短会话和长会话样本：20/200 条历史消息，包含普通段落、代码块、表格与引用；当前回答固定约 8,000 字符，按 50 次 delta/秒发送。记录 fixture 版本、浏览器、机器、构建模式和至少三次运行结果；比较必须使用同一构建模式，排除开发 StrictMode 对计数的影响。

记录历史消息渲染次数、当前回答提交频率、React commit 耗时、主线程长任务、输入交互与滚动表现。生产构建用于浏览器性能测量；需要 React commit 数据时采用同样配置的 profiling 构建。报告保存在被忽略的 `output/` 下，交接记录结论和路径。

### 实施内容

1. 将历史消息列表、流式回答展示和会话导航划清边界，使 token 文本只通知需要它的组件；流式自动滚动与辅助播报同步迁到适当订阅边界，避免父页面仍订阅全文而抵消拆分收益。
2. 对历史列表或消息行设置有效 memo 边界；稳定回调、数组、上下文值及版本导航等对象/JSX props。编辑、引用聚焦、反馈和回答版本切换必须仍能正确刷新目标消息。
3. 合并 delta 的 UI 发布，初始目标为最多每 50ms 一次；网络缓冲与展示频率分离。结束、停止、错误与会话切换处理最后一批数据和定时器，避免文本丢失、重复或跨会话泄漏。后台标签页恢复后立即显示正确状态。
4. 优先保持现有 Markdown 语义。若合并更新后解析仍是主要瓶颈，再评估分段缓存；不能简单冻结已显示段落，因为后续文本可能改变列表、表格、围栏代码和引用的解析结果。

主要入口：`pages/Chat/ChatPage.tsx`、`useChatThread.ts`、`ChatMessage.tsx`、`ChatMarkdown.tsx`、`ChatSessionRail.tsx`、`useStreamAnnouncement.ts`。

### 验收与回归边界

- 在 props 未变化的稳定流式区间，历史消息渲染次数不随 delta 次数增长；流开始/结束、用户操作等合法变化另计。
- 合并展示的最终文本与收到的 delta 完整拼接一致；普通可见标签页按设定节流周期展示，无整段积压到结束才出现的问题。
- 同一长会话样本三次运行的中位累计渲染耗时目标降低至少 30%；同时报告原始数据、输入与滚动表现。未达到时分析剩余瓶颈，不仅凭 memo 数量宣称完成性能目标。
- 首次提问创建会话后继续同一请求；停止、切换会话、未知结果对账、重新生成、编辑重答、版本切换、引用定位、429 恢复和辅助播报通过相关回归。
- 本阶段不以直接给持有请求的组件加 `key={sessionId}` 实现重置，不默认引入虚拟列表或 `content-visibility`。

## F4：共享知识库选项缓存

### 技术选择与范围

本计划选择 TanStack Query 作为共享服务端读取的基础，先迁移聊天、文档、质量页的知识库选项查询。现有 API 封装继续负责鉴权、错误结构与参数序列化；不另造通用 `createResourceStore`。`currentUserStore`、聊天写请求/SSE、上传任务和评测表单状态暂不迁移；后续迁移必须有具体重复或竞态问题作为依据。

### 实施内容

1. 增加稳定的 QueryClient 与 Provider；统一知识库选项查询的 page、pageSize、sort 等参数。不同参数的列表不能误用同一缓存，不能以选项第一页代替完整分页列表。
2. Query key 包含资源、规范化参数与认证 revision，不含 token。订阅 `tokenStore` 的认证变化，取消请求并清除旧账号数据；即使旧请求不支持取消，迟到结果也不能显示给新账号或重新填入有效缓存。
3. 初始选项缓存策略：`staleTime` 60 秒、无观察者后保留 5 分钟，过期挂载刷新；关闭焦点切换自动刷新以保持现有交互，显式刷新仍有效。该策略已进入正式规范，可按后续观测调整。
4. 读取请求的网络/5xx 失败最多自动重试一次，401、403、429 不自动重试；不为写操作开启自动重试。缓存仅改善显示，任何写操作仍以后端实时鉴权为准。
5. 知识库创建、改名、删除、恢复、权限变化后失效相关选项查询；失去权限时清理旧选项和基于这些选项的可写状态。URL 仍保留原范围，不因为选项第一页缺项而自动切换成“全部”。明确后台刷新失败与首次读取失败的展示差异，保留用户可见的刷新入口。

### 验收与验证

- 相同认证状态和参数的多个订阅共享一个在途请求；缓存有效期内跨页面不重复请求，过期、失效和手动刷新按策略执行。
- 使用延迟 Promise 验证退出、账号切换、跨标签页 token 变化以及迟到响应；新账号不看到旧账号选项。
- 创建/改名/删除/恢复和权限变化后各页面一致更新；有权限的当前选择不被普通后台刷新清空。
- 只删除已由查询层接管的读取样板；保留写入对账及跨会话隔离。运行缓存、认证和三个消费页面的回归，构建和路由分包检查通过。
- 更新 `docs/02-architecture.md`、`docs/10-frontend-spec.md` 中的查询职责和刷新约定。

## F5：会话状态与操作职责整理

### 实施内容

1. 为状态建立归属表：会话交互状态（编辑、反馈、引用、对话框）、跨会话侧栏状态（范围、分页）、请求生命周期（发送、取消、对账）。组件和 hook 按这三个职责整理，不以文件行数为唯一拆分标准。
2. 将重命名、归档、恢复、删除和导出的操作编排收敛到专用 hook，保留互斥与过期操作保护；聊天页负责组合与展示。
3. 将需要一起重置的会话交互状态集中为 reducer 的会话切换动作，避免新增字段时到处分散清理。副作用、AbortController 与定时器继续显式管理，不能只靠 reducer 解决异步竞态。
4. 如使用 key，仅作用于确定可以重建的展示/交互子树。持有首次发送的请求层在 `/chat` 创建正式会话并导航到 `/chat/:id` 时保持生命周期连续。替换 `skipSessionScopeSyncRef` 前先覆盖它保护的归档范围语义。

### 验收与验证

- 会话 A → B 后，草稿、编辑、反馈弹窗、引用预览与操作错误不串线；符合设计的侧栏范围和分页不被误重置。
- A 的慢反馈/改名/导出结果不能修改 B；合法的列表更新与全局下载行为按操作合同处理。
- 草稿首次发送跨 URL 变化不会 abort、重复发送、丢失 pendingQuestion 或清除对账信息。
- 归档、恢复、删除当前会话和非当前会话、导出、浏览器前进后退、重新生成与编辑对账通过既有及必要新增行为测试。
- F3 性能指标不因拆分重新退化；移除旧逻辑时记录由哪些行为测试保障。

## F6：抽屉与表格可访问性

### 实施内容

1. 为窄屏聊天会话抽屉补打开后的初始焦点、Tab/Shift+Tab 约束、Escape 关闭和返回触发按钮的焦点恢复；关闭时隐藏内容不进入 Tab 顺序。复用项目已有抽屉模式，遮罩后的主区不能获得交互焦点。
2. 与来源预览、确认框等嵌套覆盖层协调：Escape 只处理最上层，焦点返回仍连接的有效元素，切换宽窄布局后清理约束和 inert 状态。
3. 为 UsersPage 和 DiagnosticsPage 的响应式表格补字段标注，保留表头语义与操作控件可读名称；不通过统一替换表格组件扩大范围。
4. 核对归档/删除、会话切换入口在窄屏分支仍可用；不基于“菜单完全消失”的误报另建重复入口。

### 验收与验证

- 用现有 jsdom 与 media-query 替身验证窄屏分支的开关、焦点循环、Escape、焦点恢复、关闭后 Tab 顺序和嵌套对话框。
- 表格每个数据单元在响应式卡片规则下具有可理解的字段标注，桌面表格语义保留。

## 长会话后续结果（2026-10-08）
