## 信息来源与维护

- 实现行为以当前代码和对应规范共同核对；数据库部署执行 [SQL 迁移](../backend/migrations)，文档中的结构示例不是初始化脚本。
- 同一事实只在所属专项规范定义，其他文档链接引用；API 和权限矩阵不复制到实施计划。
- Agent常驻底线在根AGENTS，推进/Git/子代理在开发约定，风险/验收与实际结果在验证文档；交接/待办/LESSONS各自保留状态、未完成项和经验，引用规则来源。
- 公共 API、schema、默认值或 RAG 行为变更时更新对应规范；验证记录必须注明版本、环境和未覆盖范围。
- 当前交接不追加逐日施工日志，不保存旧 PID、临时端口或已失效的部署判断；当前环境状态未经检查时标为未核实。
- 已完成计划、重复验收步骤和失效的审查结论不另留一份现行合同。历史实施过程查 Git；有价值的测量与证据入口收录在验证文档，未关闭事项收录在待办。
- 调研建议不作为现行合同：采纳并验证的行为归所属规范，其余保留稳定编号和待核对状态。移除未提交的原始材料前保存内容快照及迁移去向，不能只依赖Git恢复。
- `output/`、`backend/tmp/` 中的本地验收产物通常被 Git 忽略，克隆仓库后不保证存在，也不能代替当前版本复验。
