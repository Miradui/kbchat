日期：2026-10-08。按用户选择完成第 1、2、5 项：初次直接定位底部、聊天历史分页减少首屏挂载、真实模型 PDF 引用高亮验收。未将性能脚本纳入 Git，未改测试 worker 配置；Rerank/回答质量、标题异步化和单实例任务租约继续暂缓。

## 实现

- 普通打开会话请求最近 50 条消息，首个已加载渲染通过布局阶段立即定位到底部；空流式组件不再覆盖该位置。上滚到顶部附近自动读取更早历史，也保留按钮；前插时保持当前可见消息锚点。
- 历史 API 保留无参数全量协议，增加 `limit/before/since/revision`。按时间和 ID 稳定排序，页首扩展到完整问题及其回答版本，所以 50 是软上限。迁移 033 增加会话/时间/ID 复合索引，所有读取保持 GORM、会话归属和逐库权限校验。
- 写后只刷新已加载范围，历史变化冲突可重新加载；读取失败保留现有内容，迟到请求不会覆盖切换会话或新写入。未知写入跨刷新仍全量对账，并修正“新加载的老回答被误判为重新生成成功”的边界。
- 全文查找和未加载消息深链接按需展开完整历史；展开前不报告没有结果。导出保持完整。已加载的消息不会卸载，本轮没有虚拟列表，模型历史上下文和生成规则不变。

稳定合同见 [API](04-api-design.md#get-chatsessionsidmessages)、[前端规范](10-frontend-spec.md)、[数据库](03-database-design.md#chat_messages)、[部署指南](13-deployment.md#聊天历史分页发布迁移-033)。

## 真实模型 PDF 引用

新建三页中文 PDF，真实上传→解析→切片→Embedding→自动会话浏览器 SSE 问答→持久化→点击模型实际引用→PDF.js 高亮。当前配置 `RERANK_ENABLED=false`，未改变模型、检索默认或质量参数。

实际问题：星桥项目的日备份保留多久？月度归档保留多久？请分别引用资料。

实际模型回答：

> 星桥项目的日备份保留 **35天** [source: 2]。
>
> 星桥项目的月度归档保留 **12个月** [source: 1]。

核对持久化 assistant 的实际使用编号：来源 2 对应 PDF 物理第 2 页，来源 1 对应第 3 页；原始 citations 还包含第 1 页资料，不将其描述为仅返回两条候选。两个高亮的完整规范化文本均与对应真实 chunk 一致，不注入或替换聊天引用。

浏览器验证两页定位与高亮、文字选择、上一页/下一页返回、高亮随页面移除/恢复、125% 缩放；同一个 PDF 原文件仅下载一次，无高亮运行时错误。三页提取摘要正确，原文件字节与上传一致，viewer 下载 403。真实服务仅用当前 Embedding/Chat 和 PostgreSQL；缓存为 miniredis、存储为临时本地目录，不作为真实 Redis/MinIO 验收或回答质量校准。
