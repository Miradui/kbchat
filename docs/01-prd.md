# 产品说明

## 定位与用户

企业知识库问答系统把内部制度、FAQ、产品手册和技术文档转化为可检索、可问答的资料。面向员工、客服/售前、运营、研发支持与管理人员，重点是带来源的资料问答和持续改进知识质量。

## 核心流程

登录 → 创建或选择有权限的知识库 → 导入资料 → 等待解析/切片/Embedding → 自动或指定范围提问 → 召回与Rerank → 回答与引用 → 查看原文、反馈或回归评测。

## 支持边界与非目标

- DOCX仅解析正文、标题、列表和表格的文字；不支持图片、公式、文本框、DOCX OCR或旧 `.doc`。
- 表格只读取已保存值，保留工作表和原始行号；不计算公式、执行宏、支持旧 `.xls`，也不提供跨表统计分析引擎。
- PDF OCR默认关闭，仅处理无原生文字页；复杂版面、手写与低清识别不保证准确。引用无坐标时仅定位物理页，不猜高亮。
- 存储支持本地文件和私有MinIO；文档处理保持单实例，不承诺分片断点续传。
- 不做多租户、SSO、复杂RBAC、合规审计日志、其他对象存储或生命周期管理、公开注册、计费/额度系统。
- 当前dev已有进程内诊断、OTel Trace/Metrics及可选的Prometheus/Grafana观测栈；外部通知和集中日志未接入。真实观测部署仍需按目标验收，见 [可观测性](38-observability.md) 与 [有效待办](15-backlog.md)。

## 成功标准

1. 用户能完成导入、处理、提问、查看引用和原文的闭环；处理失败有明确状态与可恢复建议。
2. 知识类回答只依据本轮授权资料；资料不足时说明缺口。通用知识/会话类可跳过检索，明确不带知识库引用。
3. 标准检索经过Rerank，引用只来自最终进入Prompt的片段；关闭或降级不得伪装成已精排。
4. 自动、固定多库与指定文档范围都不得扩大到无权资料；归档、删除和撤权保持现行合同。
5. 新环境能按README和显式迁移启动，受保护资源拒绝无权访问，错误可追踪。
6. 发布结论有对应版本、环境与证据；测试通过不能替代真实回答质量、备份恢复或业务部署验证。
