# PRD

## 产品定位

企业知识库问答系统用于把企业内部文档转化为可问答的知识库。用户上传文档后，系统自动解析、切片、向量化，并通过 RAG 流程生成带引用来源的答案。

## 目标用户

1. 企业员工。
2. 客服和售前。
3. 运营人员。
4. 研发支持人员。
5. 管理人员。

## 核心场景

1. 员工上传制度、FAQ、产品手册、技术文档。
2. 系统处理文档并建立向量索引。
3. 用户在指定知识库内提问。
4. 系统检索相关片段，经过 Rerank 精排后生成答案。
5. 用户查看答案和引用来源，确认依据。

## MVP 功能

| 模块 | 功能 | 说明 |
| --- | --- | --- |
| 用户 | 登录、退出、当前用户 | 使用账号密码和 JWT |
| 知识库 | 创建、列表、详情、编辑、删除 | 按所有者和成员权限访问 |
| 文档 | 上传、列表、详情、删除 | 展示处理状态和错误 |
| 文档处理 | 解析、清洗、切片 | 支持 txt、md、pdf、docx；扩展 xlsx / UTF-8 csv，保留表头、工作表与行号 |
| Embedding | chunk 向量化 | 写入 pgvector |
| 检索 | pgvector TopN 粗召回 | 必须按知识库过滤 |
| Rerank | TopK 精排 | 标准链路，默认开启 |
| 聊天 | 会话、消息、问答 | 基于 RAG 生成回答 |
| 引用 | citations | 来源必须来自最终 Prompt chunks |

## 已实现的工作台能力

1. 知识管理：树形分类、多标签、收藏、批量操作、活动记录和回收站。
2. 文档管理：任务进度、取消与重试、内容查重、版本替换、过期提醒、预览和引用片段定位。
3. 问答体验：多轮与流式回答、首问命名、回答版本切换、会话查找、反馈和导出。
4. 质量运营：知识缺口、测试问题集、回归评测、历史运行和配置对比。
5. 账户与协作：资料、密码、头像，以及 owner / manager / editor / viewer 的知识库能力矩阵。
6. 系统诊断：依赖、任务和模型调用状态；当前要求登录，系统级角色收紧仍列在 `12-handoff.md` 的待办中。

接口、字段与权限以 `04-api-design.md` 为准，页面行为见 `10-frontend-spec.md`。知识库公开标记只用于展示和筛选，不自动向非成员授予访问权。

2026-10-13 用户选定的扩展包含：回答收藏与个人备注、同一文档替换链的文本对比、从指定回答版本创建会话分支、支持变量的个人提问模板、文件夹 / ZIP 批量导入、XLSX / CSV 资料入库。表格属于可检索资料，不增加统计计算、公式重算或跨表分析引擎；版本对比不比较版式。具体交付与验收见 [扩展计划](28-feature-extension-plan.md)。

## 用户流程

```text
登录系统
-> 创建知识库
-> 上传文档
-> 等待处理完成
-> 进入聊天页
-> 选择知识库提问
-> 查看回答和 citations
```

## 文档状态

```text
uploaded
parsing
chunking
embedding
completed
failed
```

状态含义：

1. `uploaded`：文件已上传，尚未开始处理。
2. `parsing`：正在解析原始文档。
3. `chunking`：正在切片。
4. `embedding`：正在生成向量。
5. `completed`：处理完成，可用于问答。
6. `failed`：处理失败，需展示错误原因。

## 成功标准

1. 用户能完成从上传文档到聊天问答的完整闭环。
2. 聊天回答包含 citations；无相关内容时明确说明知识库依据不足。通用概念类问题不进入知识库检索，由模型直接作答并明确不带引用。
3. 检索范围严格限制在当前知识库。
4. Rerank 后的 TopK chunks 用于 Prompt 和 citations。
5. 文档处理失败时用户能看到失败状态和错误信息。
6. 新环境能按 README 启动，受保护资源拒绝无权访问，API 错误格式一致。

## AI 开发约束

1. 不扩展多租户、SSO、复杂 RBAC、审计日志、非 MinIO 对象存储或生命周期管理；存储支持本地文件和私有 MinIO S3。DOCX 仅支持正文、标题、列表和表格的文本解析，不包含图片、公式、文本框或 OCR。
2. 不要把引用来源作为纯前端展示拼接，必须由后端返回。
3. 不要在回答中编造知识库未提供的信息。
4. 不要让聊天接口搜索用户无权访问的知识库。
