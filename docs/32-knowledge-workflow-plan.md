# 六项知识工作流改进计划

计划日期：2026-10-18，实施及验收：2026-10-19。用户选定：指定文档提问、聊天草稿自动保存、历史引用版本提示、跨库质量管理、TXT / Markdown 在线编辑、OCR 原图对照与校对。要求先写计划再实现；网页链接入库不在本轮范围。

## 交付目标与顺序

| 阶段 | 功能 | 完成标准 | 依赖 |
| --- | --- | --- | --- |
| A | 聊天草稿自动保存 | 切换会话、页面刷新后恢复未发送文本，账号隔离，确认发送成功才清理 | 无 |
| B | 指定文档提问 | 单份/多份文档创建固定范围会话；所有召回路径只检索选中文档，历史、重生成、分支保持范围 | 既有多库鉴权及版本策略 |
| C | 历史引用版本提示 | 引用显示是否已有有效新版，可查看差异并用当前有效资料重新提问，旧回答依据不变 | B、既有版本链 |
| D | TXT / Markdown 在线编辑 | 原始正文编辑、保存为新版本、任务处理与版本对比贯通，失败保留编辑内容 | 既有上传凭据及版本替换 |
| E | OCR 原图对照与校对 | 按页对照原图和识别文本；校对保存为新版本，引用可识别人工校对来源 | D 的版本编辑流程、已发布 PDF 文本快照 |
| F | 跨库质量管理 | 自动/手动多库的个人质量视图及相应评测范围；问题处理状态连接补资料、复测和人工确认 | B、既有质量和评测模块 |

每阶段交付实现、受影响回归和规范更新。先完成相对独立的草稿保护，再贯通范围、版本和内容维护，最后补全质量反馈流程。阶段状态只在证据存在后更新。

## A. 聊天草稿自动保存

### 行为

- 按账号与会话保存未发送正文；新会话按选择的知识库/文档范围区分。切换会话不覆盖另一份草稿，刷新后恢复。
- 第一版存于当前浏览器，不增加跨设备同步。采用独立命名空间、版本标记、数量/大小与保留时长上限；存储不可用时仍可正常输入。
- 输入及时保存；只有确认该次提问已保存成功才清除对应文本。失败、停止、发送状态未知以及返回前用户继续输入时，不误删新内容。
- 账号切换立即隔离内存状态，退出时清理相应本地草稿。403/404 清理失效会话草稿；模板插入、历史窗口、编辑原问题与新提问草稿互不混淆。

### 验收

切换 A/B 会话及不同新会话范围、刷新、退出/换号、存储超限或禁用、失败重试、成功回执迟到、发送中继续输入、无效会话清理。

## B. 指定文档提问

### 行为与范围

- 新会话增加“指定文档”范围，支持选择 1–20 份同库或跨库文档，最多涉及 5 个知识库；文档详情提供“针对这份资料提问”，文档列表支持从勾选项进入。
- 文档范围持久化在会话中，显示文件名及版本。范围固定到所选文档版本；切换范围创建新会话，避免悄悄改变既有会话含义。
- 自动模式与显式文档选择互斥。已有单库、多库、自动会话行为保持；参数非法、重复、超限、跨库归属不符或无权限时在模型调用前拒绝。
- 显式选择历史版本允许针对该版本阅读和问答，界面明确标记；“当前有效版本”是另一个显式动作。文档范围不会因库级当前版本策略而无提示扩大或置空。
- 所有向量召回、关键词召回、候选计数及精确回退在数据库查询阶段应用同一文档范围；不能先全库 TopK 再过滤。Rerank 和 Prompt 仅接收范围内结果。
- 发送、流式、编辑、重生成和分支共用范围。会话归属与全部知识库依赖继续校验；文档移动、删除、失权后不得自动放宽为全库，返回可操作的范围失效提示。
- 历史回答快照继续可读，但重新生成前重新验证选中文档和当前权限。统计、导出、会话搜索沿用既有授权边界。

### 数据与接口

- 扩展创建/读取会话 DTO、会话范围持久化及检索内部参数；新增字段 camelCase，迁移在 043 之后顺序编号。
- 文档 IDs 不能替代知识库所有权/成员权限验证；分支复制原范围。响应只返回有权读取的文档元信息。

### 验收

同库干扰资料不入 Prompt、多库同名文件、只选一个版本、全部召回与回退路径一致、空结果不扩大范围、持久化/刷新/导出/分支、无权 ID、移动/软删/恢复/永久删除、撤权与并发变更。

## C. 历史引用版本提示

### 行为

- 在引用原文面板显示“已有新版”“新版尚未发布，仍使用当前有效版本”等可证实状态；版本替换与按时间判定的“可能过期”分开表达。
- 当前有效版本沿同库替换链选择最新已发布内容；新版失败/取消仍使用旧版。元信息读取遵循同样权限，不泄漏不可访问的新版文件名。
- “查看差异”复用既有版本对比；旧回答、引用摘录及来源版本不被改写。
- “按当前有效资料提问”创建明确显示新范围的新会话并填入原问题，由用户发送；不自动重写旧回答、不暗中调用模型。多份引用按文档去重并校验全部目标。
- 无新版、版本链断开、删除或无法读取时显示准确状态，不把更新时间当作版本生效证明。列表读取批量获取必要元信息，避免每张引用重复加载全部版本文本。

### 验收

连续替换、失败/取消新版、重处理保留已发布快照、同库/跨库引用、未知旧记录、对比入口、新范围与原问题保持、撤权/删除、历史回答内容不变。

## D. TXT / Markdown 在线编辑

### 行为

- 有内容写权限的用户可在详情打开 TXT/Markdown 原始正文编辑器；读取完整且有界的原始 UTF-8 文本，不能拿截断预览作为保存内容。
- 保留标题/格式，编辑内容可预览；取消或离开时保护未保存修改。纯文本不执行 HTML，Markdown 继续沿用现有安全渲染。
- 保存生成新的文档版本并进入现有解析、切片、Embedding 流程；沿用稳定请求 ID、存储清理与替换链事务。相同请求重试不创建重复版本。
- 以打开时的版本作为保存前提；另一用户已替换该版本时显示冲突并保留本地内容，不覆盖对方修改。无改动不产生新版本。
- 成功后可查看新文档进度；处理失败时旧版本仍可检索。文件类型、字节上限、空文本及权限沿用并补齐校验。

### 验收

TXT/Markdown、中英文、原始换行与正文完整性、无改动、空内容/超限、并发保存、丢失回执、撤权、存储失败、处理失败保留旧版本、新版引用及版本对比。

## E. OCR 原图对照与校对

### 行为

- 针对已成功发布 OCR 文本的 PDF，提供左侧物理页原图、右侧该页识别文本的校对界面；翻页始终对应同一物理页，显示机器识别或人工校对来源。
- 原图访问继续要求现有原文件读取能力；保存要求内容写权限。无快照的旧 PDF 提示先重新处理，不能读取一份当前解析结果却冒充历史识别结果。
- 第一版只编辑已有 OCR 页正文，不修改原生文字页、不添加或删除 PDF 页、不修改 PDF 二进制，也不扩展 DOCX OCR 或复杂版面编辑。
- 校对保存生成独立的新文档版本：保留原始 PDF 的可追溯副本，保存完整页文本基线及校对覆盖，worker 使用该基线重新切片和向量化。原始机器识别版本保持可读。
- 校对来源进入片段、回答引用、历史、预览、导出及版本对比。校对文字不伪装成 PDF 原生文字；没有坐标时不画猜测高亮。
- 保存复用 D 的幂等与版本冲突保护。每页/整份字节、页数及处理预算有上限；取消或失败不发布部分新内容。
- 后续重新处理校对版使用保存的校对基线，避免 OCR 再运行覆盖人工文字；重新识别原图作为未来独立动作。

### 验收

中英文识别纠错、混合原生/OCR 页、逐页切换草稿、部分页校对、重处理结果稳定、旧/新引用和文本差异、原文件权限、并发冲突、幂等重试、取消/失败及资源上限。

## F. 跨库质量管理及缺口处理

### 权限与展示

- 保留现有单库运营视图；新增“我的跨库/自动问答”范围，先覆盖本人会话，按自动、手动多库和指定文档区分。
- 不直接删除单库 SQL 过滤后向某一库管理员展示完整跨库回答。查看会话/问题、引用、测试快照和历史结果均需满足会话归属及全部来源库权限。
- 统计与列表使用同一范围和逐库权限条件，避免计数泄漏；每条回答只统计一次。撤权、软删除或永久删除继续遵守当前会话访问合同。

### 评测与处理流程

- 评测用例和运行保存范围快照，可表达单库、固定多库、自动或指定文档；生成请求复用正式聊天检索链路，保留原有单库用例兼容。
- 自动评测记录实际来源及执行时的可访问范围；固定范围重跑不悄悄变成全库。运行失败/取消与规则不通过分别统计，禁止以引用数量或检索分数充当正确率。
- 为缺口建立用户级处理记录：待处理、待复测、已解决，可记录处理备注、补充文档、关联测试问题及最近复测结果。
- 从缺口进入补充资料，再回到相同范围复测；保存运行关联。最终“已解决”由用户确认，不因新增文档或模型返回文本自动认定解决；可重新打开。
- 幂等保存、重复问题关联、已删测试用例、资料撤权、运行中取消/刷新均有清晰行为；不自动启动真实模型定时评测。

### 验收

自动/固定多库/指定文档统计与列表一致、同一回答不重复统计、不同用户和库管理员不越权、撤权后全部视图隐藏、范围快照及重跑、补资料→复测→人工解决→重新打开、取消/失败保留处理记录。

## 验证、文档及环境边界

- 本地 fixture 测试覆盖关键业务路径和权限/并发/失败路径，修复本次变更导致的失败后重跑受影响项；最终执行后端 `go test ./...`/`go vet ./...`，前端全量测试、类型、lint 与构建。
- 新迁移验证从空 schema 顺序执行及重复执行；真实数据库测试使用独立 schema，浏览器按 1920×1080 验收。构建、临时文件与进程使用独立路径/端口，不覆盖当前业务服务。
- 联调优先本地模型替身；不更改模型、Rerank 或检索默认，不声称 fixture 通过代表真实回答或 OCR 通用准确率提升。保持单实例，任务租约继续暂缓。
- 同步 `03-database-design.md`、`04-api-design.md`、`05-rag-pipeline.md`、`09-error-codes.md`、`10-frontend-spec.md`，按实际改动更新配置/部署与交接；新增验收记录列出证据和未满足项。
- 业务 public 按现有交接仍到 033，本轮不迁移业务库、发布或推送；不改根 `.env`，不接管用户已有 `backend/cmd/dbquery/`、`backend/cmd/tmp-explain/`。部署前需包含既有 034–043 及本轮后续迁移。
