## 文档统计与 PDF

统计复用列表的 q、knowledgeBaseId、fileType、所有者/成员能力和软删除条件。q 同时匹配文件名和知识库名；非法 UUID 返回 400，不可访问或不存在的库返回全零。管理员身份不扩大读取权限。`processing` 包含 uploaded/parsing/chunking/embedding；`failed` 沿用文档状态语义，包含已取消但 document.status 为 failed 的条目。

四个桶来自同一个 SQL 查询快照，不加载文档实体、任务或进度。列表与统计仍是独立请求。前端保留取消、迟到结果守卫、静默轮询及统计失败时的未知状态。真实浏览器首次 `/documents?...` 和 `/documents/counts` 各一次；搜索或类型变化各更新两者，状态切换只更新列表。

PDF 摘要为 `{totalPages, textPages, pagesWithoutText}`，存储列为可空 JSONB `documents.pdf_text_summary`，API 字段为 `pdfTextSummary`。只有空白/BOM 的页也计为无文字；使用从 1 开始的物理页码，连续页合并为范围，超过 20 个页码可展开查看。无文字不等于扫描件或损坏，不增加 OCR。

摘要在完整解析成功后、切片和 Embedding 前写入，因而全空 PDF 报 `empty_content`、后续 Embedding 失败时仍保留本次解析信息。解析出错不保存部分摘要；取消/失效任务不能覆盖结果。重处理排队及开始解析清除旧值。浏览器验收发现重处理响应仍携带授权时加载的旧对象，已同步清除响应中的摘要并补服务层回归。

旧文档、非 PDF 或尚未完整解析的记录保持 `null`；摘要缺失不证明每页都有文字。列表不返回可能较大的页码数组。viewer 可读取摘要及片段，下载原文件仍要求 editor 及以上。

真实样本经 ReportLab 生成、Poppler 渲染、pypdf 提取检查及浏览器目视检查：

| 样本 | 物理页面 | 结果 |
| --- | --- | --- |
| mixed.pdf | 文字、空白、仅图片、文字 | 完成入库；4 页中 2 页有文字，无文字页 [2,3]；chunks 保留 p.1/p.4。 |
| empty.pdf | 空白、仅图片、空白 | `empty_content`；仍返回全部 3 个无文字页，详情可核对原 PDF。 |
| text.pdf | 两页文字 | 完成入库；textPages=2、空数组，界面没有无文字警告。 |

三份原文件下载字节与上传文件一致。viewer 摘要/片段可读、下载返回 403，浏览器不请求 PDF 原文件；无关用户读取返回 404。重处理真实通过：响应摘要变 null，界面移除旧提示，解析后出现新提示，原文件不重复下载。Embedding 失败保留摘要、失效任务保护、单项/批量重处理清除另有本地 fixture 回归。

## 首屏测量方法

环境：Windows 10.0.22000、Ryzen 7 5800H、16 个逻辑 CPU、约 16 GiB 内存、Node 24.6.0、Headless Chrome 154、1920×1080。使用当前真实 ChatPage/AppShell/Markdown 代码的独立生产构建，关闭 StrictMode。接口使用确定性的 JSON 克隆响应，用户和助手各占一半，每条助手消息含标题、段落、表格、代码和引用，不包含真实网络/API/模型延迟。

每个样本使用新页面。资源冷缓存清理并禁用 HTTP 缓存；热缓存先在独立页面预热，逐项验证 JS/CSS 传输字节为零。这里的冷/热只指资源缓存，不代表重启浏览器、冷操作系统缓存或固定 CPU 频率。

四组各 4 种长度 × 3 轮：普通生产冷缓存、普通生产热缓存、生产热缓存加 trace、生产热缓存加 React profiling。普通生产组没有渲染/解析计数注入。profiling 与 trace 不混入普通生产首屏统计。单元测试与真实联调在正式采样前结束，仍不能控制整台机器的所有后台活动。

- 正文首屏：导航开始到所有历史消息进入 DOM、字体就绪并经过两次 rAF。FCP 仅是较早的首次内容绘制，不等同于完整历史可读。
- 滚动停稳：页面自身的初始平滑滚动到达底部阈值，连续两帧位置稳定；单独计量这段时间。
- CDP Layout/RecalcStyle/Script：从导航前到滚动停稳后的观察器收尾读取，为累计值，不能当作一次长任务，也不能相加等同于页面耗时。
- Paint：trace 中主线程 Paint 区间的并集，消除嵌套事件重复计数，分别计量正文首屏前和随后的滚动阶段。不包含 GPU 光栅化和合成完成时间。

48 个样本均通过完整历史、输入框可用、底部位置、无横向溢出、无运行时错误、无意外 API、可见性、视口和缓存校验。两轮预采样单独保留，不进入正式统计。

Paint 存在父子嵌套事件。1000 条的事件 duration 直接累加中位数为 668.5 ms，去重后为 338.7 ms；报告只使用后者。各阶段分别取中位数，其和不一定严格等于总中位数。几百毫秒的累计 Paint 分布在约 1.5 秒滚动中，不是一帧阻塞几百毫秒。

profiling 组 20/200/500/1000 条累计 React `actualDuration` 分别为 110.9/255.4/461.1/590.4 ms；首次 Markdown 解析次数为 10/100/250/500，恰好每条助手消息一次，没有额外历史重解析。对应首屏为 494.5/828.0/1326.1/1601.1 ms；profiling 有额外开销，不能当作普通生产结果。

后续有两个可测目标：首次进入长会话时减少全量挂载成本；初次定位到底部时避免遍历整段历史的平滑滚动。若启动分页或虚拟列表，需保持不定高 Markdown、浏览器查找、消息定位、引用及滚动恢复。`content-visibility` 可单独对照布局/绘制，但不会消除首次 React/Markdown 执行。本轮只测量，未实施这些改动。

## 自动跨库真实链路

隔离 PostgreSQL schema 为 `rag_accept_20261008_doc_followup`，完整执行 33 个 SQL 文件（001–032，含两个 010 文件）。使用当前真实 Embedding/Chat 配置。初次轻量 Embedding 探测遇 EOF，随后真实上传成功；此前报告中的上游 503 不再作为本轮未验收原因。

自动会话在第二个库创建前建立。首轮时 viewer 可访问星舟库与空库，雪峰库尚未授权；授权后沿用同一会话提问：

| 轮次 | 通道/问题 | 实际结果 | 本轮持久化来源顺序 |
| --- | --- | --- | --- |
| 1 | API SSE，星舟日备份保留规则 | 35 天，引用星舟文件 | 星舟 |
| 2 | API JSON，新授权雪峰计划采样间隔 | 17 分钟，引用雪峰文件 | 雪峰、星舟 |
| 3 | 浏览器 SSE，回到星舟日备份 | 35 天，引用星舟文件 | 星舟、雪峰 |

来源顺序随问题改变；当前阈值下第二、三轮仍包含另一库候选，不将其描述成每轮只检索一个库。三份回答和 citations 读取一致，会话累计依赖两个来源库；intent/answer 各 3 条用量记录全部关联回答消息。

新增授权后无需重建会话即可使用新来源；viewer 在浏览器中打开雪峰原文并看到对应内容。无关用户、库所有者或管理员均不能读取该 viewer 的会话。撤销已使用的雪峰授权后，会话详情、消息、导出拒绝访问；即使下一问只问星舟，浏览器仍按整个历史依赖拒绝发送，清空旧消息/来源并返回新会话。重新授权后恢复三轮历史。

此环境使用临时 miniredis 和本地临时存储，不能代表真实 Redis/MinIO。本轮 `RERANK_ENABLED=false` 与原配置一致，未验证精排成功路径或调优回答质量；三题事实核对仅用于确认来源链路。
