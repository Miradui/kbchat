# 开发约定

本文件维护任务推进、上下文、Git、子代理、执行边界和记录方式。常驻工程底线在 [AGENTS.md](../AGENTS.md)，风险与验收的活跃定义在 [验证文档](14-verification.md#任务风险与验收)，领域合同按 [文档导航](README.md) 读取，不在这里复制另一套。

## 任务推进

1. 确定可验证的交付结果与授权范围，查阅 [交接](12-handoff.md) 和 [有效待办](15-backlog.md)。任务可为 Exploration、Implementation、Bugfix、Refactoring、Documentation 或 Infrastructure，按实际影响选择 L1–L3，类型不替代风险。
2. 读本次需要的规范和实现，列出需改文件、关键边界与适用验收。混合任务按最高风险部分安排相应验证，独立文档部分仍可按 L1 验收。
3. 连续完成实现、受影响检查、失败修复及文档同步；先检查受影响包/文件，有跨模块影响、新失败或未解疑点时才扩大回归。
4. 根据必需验收判断完成，记录实际成功、失败、部分完成或结果未知，以及未运行原因和剩余工作。仅完成文件修改不等于完成实现任务。

用户已授权且范围明确的读取、修复、夹具测试和必要准备直接推进；不重复请求许可。缺少关键决定、目标或权限时，先把已授权部分做到可审阅，再请求所缺信息；等待或工具输出不扩大授权。外部发送、合并、发布及破坏性真实操作按用户授权和运行环境权限执行。

## 上下文与修复

- 主代理完整亲读本次所需的产品、架构、设计、交接和待改代码/规则；子代理可定位，摘要不能替代这些原文。复用旧阅读前确认文件未变。
- 已知位置的小文件、单一事实和即将修改的代码直接处理；检索先用 `rg` / `rg --files`，宽检索按下节委派。重要结论保留路径、行号、符号及必要原文。
- 修复先区分候选解释和已证实根因，检查相关入口及共享机制；用户已确认的产品决定不在修复中反转，草案和旧计划不自动进入范围。
- 超时、取消、断连或观察失败保留为未知/未确认，不直接推断未执行、已撤销或成功；特别是写操作需按原请求编号或实际回执对账。

## Git 与内容身份

- 修改前检查 `git status --short --branch`、`git diff`、`git diff --cached` 和未跟踪内容；只改本次范围，保留用户文件、其他任务差异及暂存状态。来源不明的改动先核实，不把全体差异归给本次任务。
- 不自行 reset/clean、强推、覆盖用户内容、提交、合并、打 tag 或发布。已有明确授权时按其范围执行，提交前复核文件归属，不取消他人暂存；只清理自己创建且确认归属的资源。
- 有 HEAD 且相关输入均已提交、未变化时可用 SHA 标识版本；有未提交/未跟踪输入时同时保存相关文件内容快照或 SHA-256，路径清单和空 diff 都不能代替内容身份。无 HEAD 如实记录分支和相关快照，不擅自初始化 Git。
- 最终验收绑定实际被检查的规则、代码、配置、语料及必要产物；之后改变输入须补验受影响部分并更新摘要。派生报告可排除循环哈希并说明原因，影响行为或被测规则的内容不得排除。
- CI 与最终目标提交的要求在验证文档定义；未查询远端时不推断 CI 结果或分支保护，历史通过只能作为当时的证据。

## 子代理

子代理是探索与核验探子，主代理承担编排、方案取舍、核心修改和最终验收。

- 在工作任何阶段，宽检索、跨文件/目录读取、大型非奠基材料、长任务现状复核和独立核验优先派发；只有能减少主线程上下文、提高并行度或提供独立证据时才派，不为次数制造任务。
- 已知小文件、少量代码、单一事实、待改确切代码和奠基性文档由主代理直接处理；派发/等待/复核成本不低于亲读时直接处理。
- 任务自包含：说明路径范围、具体问题、只读约束和期望输出；精度重要时要求 `file:line`、符号、关键原文及证据缺口。多个独立探索在同一轮并发派发，并发额度以实际工具为准。
- 使用默认配置；工具支持 `agent_role` / `agent_type` 时明确为 `default`，不使用 explorer/worker 等角色。派生必须显式 `fork_turns="none"`，不复制主线程历史；工具不支持所需能力时如实说明并直接处理。
- 派发后主代理立即等待，停止其余分析、检索、命令和文件修改，直到本轮全部返回；可向用户简要报告已知进展。每个探子只用一轮，不复用或追派；收到最终结果后，若有 `close_agent` 则立即关闭，缺少该工具不虚构关闭。
- 每个探子从派生起累计运行满 **10 分钟**仍未完成时必须介入：查状态/运行记录，采用已有可用消息，停止异常探子，再决定是否拆小重派，不继续盲等。
- 结果只是压缩线索，可能有遗漏；主代理沿提供的出处抽查重要或可疑结论，不重新通读全部外包材料。最终方案、文件修改与验收结论仍由主代理负责。

## 执行边界

- SQLite、临时文件、HTTP/API 替身和 jsdom 夹具可直接运行；修复本次引入的失败后重测，无需逐步确认。Go SQLite 测试需要 CGO 和 C 编译器。
- 默认夹具的前提是真实服务测试开关未启用。运行前核实继承的 `RAG_TEST_*` 开关；只检查是否启用，不输出凭据。若本次只授权夹具，在测试子进程中移除真实入口开关，不改用户持久配置；具体开关及副作用以 [真实服务入口](14-verification.md#真实服务入口) 为准。
- `doctor` 会访问实际配置的服务；`migrate`、`seed`、重建工具及 server 启动后的 worker 可能写数据。执行前核实目标、现有授权和实际影响；目标不明时先完成独立准备，再确认所缺信息，已有授权不重复请求。
- 真实 PostgreSQL/MinIO、模型费用、OCR、浏览器或发布验收按任务完成条件和授权目标执行。夹具、一次性数据库、真实业务环境和用户反馈分开记录；本地集成浏览器只需 **1920×1080**。
- 纯文档任务核对结构、路径/锚点、命令与规则语义；不用应用构建替代文档检查，也不为一次检查新增依赖或测试框架。
- 使用当前可用 shell，并为每次命令显式设置工作目录；README 的 PowerShell 与部署文档的 Bash 是各自环境示例。先读取实际脚本/CI，不能据历史文本启动缺失配置或把零测试匹配当成通过。

## 进度与 LESSONS

- 复用已有位置：[交接](12-handoff.md) 只保留继续工作需要的当前状态与限制，[待办](15-backlog.md) 保留未关闭/暂缓事项，[验证记录](14-verification.md#记录格式) 保存实际结果与证据。详细结果只写一处，其余链接引用。
- 开始确定或更新稳定任务记录；重要里程碑、范围变化、阻塞、验证失败和交付时更新。小型一轮任务可在交付时一次记录，不给每个工具调用写日志或另建全套文档。
- 保留已有 `AUD-*`、需求 `R01–R09` 等 ID、父子关系、完成条件与历史证据；父项只有全部必需子项通过才完成。新增必需范围重新开启父项，回归关联原任务并追加失败，不覆盖旧通过/失败记录。
- [LESSONS](17-lessons.md) 只记录真实事件、后果、失败/修复或 Done right 正例及出处；没有值得沉淀的事项可注明“无新增事项”，不为每次任务凑教训。
- `Seen N×` 只累计不同日期、真实工作事件支持的复盘确认；同日重复读取、多个失败或复核不加次数。新经验在三个不同日期均有实际复盘证据后可晋升正式规范，保留原 ID、三日证据和晋升日期，并把活跃规则放回唯一维护位置；已成立的正式要求不受此计数门槛影响。
- 交付说明实际问题、改动职责、验证结果及未满足项，链接记录与文件。历史部署或测试状态未经本轮核实须明确为历史/未知；不写旧 PID、临时端口或把其他分支的结果当作当前源码。
