# 文档工作流扩展计划

日期：2026-10-14。用户选择第 **1、2、4、6** 项，要求先列计划、随后实现，并按功能点提交 Git。按下列顺序交付，每项包含实现、相关回归和正式规范更新。

## 1. 上传中断恢复

- 为一次上传或版本替换分配稳定请求 ID，服务端按用户和目标知识库保存提交结果；相同请求重试只返回同一文档，改变文件或导入选项的请求不能冒用旧 ID。
- 增加按请求 ID 查询结果的接口。网络中断后先核对，已成功则继续下一文件，未成功可用同一 ID 安全重试；网络仍不可用时保留清单和恢复入口。
- 文档、处理任务、替换关系与上传凭据在同一事务内提交，保留现有对象清理、权限与重复内容选择。
- 验收：响应丢失、并发重试、替换中断、重复内容选择、撤权和连续批量上传；不得重复创建文档或断开版本链。
- 范围：整文件重试，不实现分片字节断点续传；刷新或关闭页面仍需重新选择本地文件。

## 2. 表格导入设置

- 上传前预览 XLSX/CSV 的工作表和原始行，支持选择工作表、表头所在行和参与导入的列；保留不配置时的原有自动行为。
- 将标准化导入设置随文档持久化，解析 worker、重新处理、预览、版本对比和安全重试复用同一设置。
- 保留物理行号与工作表定位；未选择的列不进入检索片段及解析文本预览。只读已保存的公式值，不计算公式或执行宏。
- 验收：多工作表、非首行表头、稀疏/空列、自定义列、非法配置、重处理与引用一致性。

## 4. 文档版本检索控制

- 在知识库设置中提供“全部版本 / 当前有效版本”检索策略；存量与新建知识库默认保留现有“全部版本”行为，由用户显式切换。
- “当前有效版本”沿替换链选取最新具有已发布片段的可用版本；新版本仍在处理或首次处理失败时，继续使用已发布的旧版本。
- 向量、关键词及精确回退使用同一策略。历史文档、原文预览、版本对比和旧回答引用继续可访问。
- 验收：旧/新内容冲突、连续替换、失败/取消/重处理、删除/恢复、多库与自动检索，以及历史引用可读。

## 6. 扫描 PDF OCR

- 使用可配置的本地 OCR 工具处理未提取到原生文字的 PDF 页面；先检查可用工具，再确定部署配置。
- 设置页数、分辨率、执行时限与输出大小限制，响应取消；工具不可用、超时或识别失败提供可操作提示。
- OCR 文本按物理页入库并参与引用，页面来源标明识别文本；PDF 原生文本高亮与 OCR 来源展示保持一致、准确。
- 更新无文字页摘要、处理进度、失败提示和部署说明；DOCX 图片及旧 `.doc` 不在此次扩展范围。
- 验收：真实扫描 PDF、中英文、混合原生文字/扫描页、空白页、取消、工具不可用与引用页码一致性。
