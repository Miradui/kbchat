# 前端规范

前端使用 React，目标是克制、清晰的企业级 AI 知识库与聊天问答产品。MVP 不做营销首页，不引入大型 UI 框架。

## 页面清单

~~~text
/login
/home
/knowledge-bases
/knowledge-bases/:id
/knowledge-bases/:id/documents
/documents
/chat
/chat/:sessionId
/search
/tags
~~~

除 `/login` 外的页面都需要 token；匿名访问受保护路由时跳转 `/login`。

## 全局应用外壳

1. 左侧主导航固定包含：首页、知识库、文档管理、问答管理、全局搜索、标签管理。
2. 不展示不属于 MVP 的“权限管理”和无功能系统设置占位项。
3. 顶栏统一展示当前页面上下文、全局搜索入口、当前用户提示和退出登录。
4. 知识库分类树只在支持分类操作的知识库工作台显示，不在首页、文档、聊天、搜索和标签页面重复显示。
5. `>= 1280px` 使用完整侧栏，`981–1279px` 使用紧凑侧栏，`<= 980px` 使用导航抽屉，`<= 680px` 使用 16px 内容边距和移动端触控尺寸。
6. 任一断点不得出现整页横向滚动；导航抽屉打开时锁定背景滚动并约束焦点，Escape 关闭后恢复触发按钮焦点。

## 登录页

功能：

1. 用户名和密码使用可见标签。
2. 支持显示/隐藏密码。
3. 提交期间禁用字段和按钮，避免重复登录请求。
4. 登录失败展示后端 `message`，并把焦点移动到错误摘要。

验收：

~~~text
登录成功后保存 token
跳转到 /home
登录失败显示后端 message
全流程可用键盘完成
~~~

## 首页

1. 展示新建知识库、导入文档和开始问答快捷入口。
2. 统计、最近知识库、最近文档和最近会话独立加载；单个接口失败不得清空其他成功区域。
3. 加载时使用预留空间的 Skeleton；区域失败时提供局部重试。
4. 展示处理中与失败文档摘要，不伪造后端状态。

## 知识库列表页

1. 展示当前用户知识库。
2. 卡片和表格优先展示可问答状态、可见性与更新时间；文档数、浏览量和问答量作为次级信息。
3. 可问答状态由列表聚合计数推导，优先级为：失败 > 处理中 > 可问答 > 暂无文档。旧后端缺少聚合字段但 `documentCount > 0` 时保守展示“处理中”。
4. 收藏保留为直接图标操作；编辑、移动到分类和删除收纳到每项的更多菜单。更多菜单支持键盘方向键、Home、End 和 Escape，并在关闭后恢复触发器焦点。
5. 单项移动使用轻量 Dialog 并复用批量移动 API；请求失败保留 Dialog 和用户选择。
6. 删除前必须使用统一确认框，删除失败保留确认框并在其中展示错误。
7. 支持分类筛选、卡片/表格视图和进入知识库详情；任一工作台 mutation 期间锁定会产生冲突的行操作、批量操作和分类操作。

## 知识库详情页

1. 知识库上下文统一提供“概览、文档、AI 问答、设置”四个入口，当前入口必须使用 `aria-current="page"` 标识。
2. 概览使用 `/knowledge-bases/:id?tab=overview`，缺少或无法识别的 `tab` 按概览处理；展示文档摘要、基础信息、标签和最近文档。
3. 文档继续使用 `/knowledge-bases/:id/documents`，保留 `intent=upload`、`documentId` 和 `chunkId` 深链合同，并在页面中复用同一组知识库导航。
4. AI 问答使用 `/knowledge-bases/:id?tab=qa`，只展示当前知识库的问答就绪状态和用户目标入口；实际提问继续进入 `/chat/new?knowledgeBaseId=:id`，不得提前创建空会话。
5. 设置使用 `/knowledge-bases/:id?tab=settings`，承载成员权限、检索配置和检索诊断。成员权限仅在首次进入设置时加载，加载完成前不得展示可写控件；离开设置后应使未完成的权限搜索请求失效。
6. 检索诊断只在用户提交问题时请求；开启调试信息后展示后端返回的真实 debug 数据，不得由前端推测或伪造。

默认 `retrievalConfig`：

~~~json
{
  "vectorTopN": 30,
  "rerankTopK": 5,
  "scoreThreshold": 0.3,
  "enableRerank": true
}
~~~

## 文档管理页

1. 知识库文档页与全局文档台账复用同一个导入 Dialog；知识库页固定目标，全局页在 Dialog 内选择目标。选择文件后先展示待导入清单，用户确认后才上传，不得打开系统文件选择器后立即提交。
2. 支持选择或拖放多个 `txt`、`md`、`pdf` 文件。前端按清单逐个调用现有单文件上传 API，逐项展示待上传、上传中、已上传和上传失败；部分失败时保留清单，并只重试失败项。
3. 客户端在上传前校验扩展名、空文件和默认 50 MiB 单文件上限；服务端校验仍为最终权威。上传期间禁止重复提交和关闭 Dialog，成功、部分失败及列表刷新失败分别提供明确反馈。
4. `/knowledge-bases/:id/documents?intent=upload` 自动打开导入 Dialog、消费 `intent` 参数并聚焦文件选择入口，但不得自动打开系统文件选择器或创建上传请求。
5. 页面首要摘要统一为“可用于问答、处理中、失败”；解析、切分、向量化等详细阶段只在文档行或详情中按需展示，不作为首屏常驻流水线。
6. 展示文件类型、大小、状态和处理提示，并支持删除和重新处理文档。批量 mutation 期间必须禁用导入入口及其他冲突操作。
7. 存在未完成文档时每 3 秒刷新；全部为 `completed` 或 `failed` 后停止轮询。
8. 列表和详情展示 `jobStatus`、`progress`、`stage`、`retryCount/maxRetries` 和 `nextRetryAt`；阶段和任务状态使用中文用户文案，旧后端缺少这些字段时按文档 `status` 推导兼容进度。
9. 全局文档台账直接展示处理进度、重试计划和失败原因；轮询成功不能清除上传或批量操作错误。
10. 手动刷新、详情变更和回收站变更后的刷新失败必须被捕获并展示。若写操作已成功而列表刷新失败，提示必须明确区分“操作成功”和“刷新失败”，不能诱导用户重复写操作。
11. `failed` 必须作为独立失败状态展示，不得显示为 100% 完成；旧后端缺少进度字段时失败兼容进度为 0。错误提示必须说明恢复方式，配置未完成时应明确提示先联系管理员修复配置，再执行重处理。

后端状态：

~~~text
uploaded
parsing
chunking
embedding
completed
failed
~~~

## 聊天问答页

1. 展示会话、消息、问题输入和发送状态。
2. assistant 回答必须展示真实 citations；无引用时展示“当前知识库中未找到足够依据。”
3. citations 至少展示 `filename`、`pageNumber`、`content`、`vectorScore` 和 `rerankScore`。
4. 后续切片优化会话操作、重试、重新生成、citations 展示体验和可见的 Rerank fallback，不改变真实 citations 的既有合同。
5. 从知识库或问答入口开始新问答时先进入草稿页，不得仅因浏览入口就创建空会话；首次提交问题时再创建会话。
6. 发送失败后保留原问题，并提供重试入口；模型或检索错误展示中文业务提示，不直接显示 Provider 原始错误。每次首次发送生成 UUID `clientRequestId`，网络结果未知时持久化 pending request，跨刷新按消息的 `clientRequestId` 对账；显式重发必须复用原 ID，不得按消息数量或文本相等推测。
7. assistant 正文中的合法 `[source:n]` 或 `[source:n,m]` 标记转换为可点击来源角标，仅当整组编号都对应本条回答的 citations 时生效；组内重复编号只展示一次，超长分组以及含无效或越界编号的标记整组保留原文。点击后定位并高亮对应来源，紧凑布局同时打开来源抽屉，并向辅助技术播报定位结果。
8. 来源卡默认展示短摘录，长原文按需展开；向量分和精排分收纳在“检索详情”中，`rerankScore=null` 明确展示为“无精排分”。
9. 重新生成失败必须显示在对应 assistant 消息内。只有明确的业务失败才能提供重试；网络中断或不确定 5xx 必须进入“结果待确认”状态，并跨刷新、会话往返持久化，只允许刷新消息并按新消息 ID 对账。检查仍无新回答后，必须由用户显式确认才能再次发起非幂等写操作；若浏览器无法持久化保护状态，则不得发起写操作。重新生成成功后直接使用接口返回的 `message` 更新线程；不得因后续列表刷新失败将已成功的写操作误报为失败。

## 全局搜索页

1. 关键词、结果类型和分页分别保存在 URL 的 `q`、`type`、`page`、`pageSize` 参数。
2. 全部、知识库、文档和内容片段筛选由服务端执行；切换类型或查询时重置到第一页，刷新和前进/后退后状态不丢失。
3. 输入停止 300ms 后以 replace 模式同步 `q`，显式提交立即同步；查询、类型或分页变化时中止过期请求，并防止忽略 AbortSignal 的旧 Promise 覆盖新结果。
4. 使用服务端 `total` 展示真实总数与前后翻页，不得用当前页 items 推测各类型总数。
5. 明确展示加载、空结果、错误和局部重试状态。

## 标签管理页

1. 列表支持名称筛选和移动端字段标注卡片布局。
2. 新建和编辑在共享 Dialog 中完成；失败后保留输入并展示后端 `message`。
3. 创建和更新成功后局部更新列表，不重新加载整表。
4. 删除前确认；删除失败时保留原行和确认框，并在确认框内展示后端错误。
5. 成功操作通过全局 Toast 通知。

## 全局反馈与可访问性

1. Button、IconButton、EmptyState、ErrorState、LoadingSkeleton、Dialog 和 Toast 使用统一语义样式。
2. 图标按钮必须同时提供 `aria-label` 与 tooltip，不使用字符或英文占位图标。
3. Dialog 支持 Escape、焦点约束、背景滚动锁定和焦点恢复。
4. 所有交互控件保留明显 `:focus-visible`；关键移动端触控目标不低于 44px。
5. 支持 `prefers-reduced-motion`；成功、警告和危险状态不能只依赖颜色表达。

## API 与代码约束

1. token 保存在 token store；API 请求统一注入 `Authorization: Bearer <token>`。
2. 401 时清理 token 并跳转登录页；错误反馈优先使用后端 `message`。
3. 页面级筛选优先写入 URL；可过期请求通过 `AbortSignal` 取消。
4. 路由页面使用 `React.lazy` 分包；`App.tsx` 只承载 Outlet，不堆叠页面实现。
5. `resources.ts` 保持兼容导出；API 字段使用 camelCase，不伪造文档状态、检索分数、Rerank 状态或 citations。
6. 知识库、文档和聊天内部优化必须分别测试并按后续计划渐进实施。
