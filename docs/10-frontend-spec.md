# 前端规范

前端使用 React，目标是克制、清晰的企业级 AI 知识库与问答产品。MVP 不做营销首页，不引入大型 UI 框架。

前后端接口缺口的发现与闭环记录在 `docs/14-frontend-api-gaps.md`；当前行为以本文件和 `docs/04-api-design.md` 为准。

## 页面清单

~~~text
/login
/home
/knowledge-bases
/knowledge-bases/:id
/knowledge-bases/:id/documents
/knowledge-bases/:id/settings
/documents
/chat
/chat/:sessionId
/search
/tags
~~~

除 `/login` 外的页面都需要 token；匿名访问受保护路由时跳转 `/login`。

### 兼容重定向

以下入口在历史版本中存在，必须继续可用：

| 旧地址 | 行为 |
|--------|------|
| `/chat/new?knowledgeBaseId=X` | `replace` 到 `/chat?knowledgeBaseId=X`，保留全部 query |
| `/knowledge-bases/:id?tab=overview` | `replace` 到 `/knowledge-bases/:id` |
| `/knowledge-bases/:id?tab=settings` | `replace` 到 `/knowledge-bases/:id/settings` |
| `/knowledge-bases/:id?tab=qa` | `replace` 到 `/chat?knowledgeBaseId=:id` |

### 深链接合同

以下 query 参数被引用卡片、全局搜索和跨页跳转依赖，不得更改语义：

~~~text
/knowledge-bases?intent=create              打开新建知识库对话框并消费该参数
/knowledge-bases/:id/documents?intent=upload 打开导入对话框并消费该参数
/knowledge-bases/:id/documents?documentId=   打开文档详情抽屉
/knowledge-bases/:id/documents?documentId=&chunkId=  定位到指定内容片段
/chat?knowledgeBaseId=                       以该知识库开始一个草稿会话
/chat?q=                                     预填充输入框并消费该参数
/search?q=&type=&page=&pageSize=             全局搜索状态
~~~

## 全局应用外壳

1. 左侧导航为每个区域提供一级入口，分两组：工作台（首页、AI 问答）与知识（知识库、文档、标签）。不得把某个区域映射到另一个区域的高亮项。
2. 不展示不属于 MVP 的功能占位项。
3. 顶栏承载面包屑、命令面板入口和页面级主操作。页面正文不重复面包屑中已有的层级信息。
4. 全局搜索通过命令面板进入，`⌘K` / `Ctrl+K` 唤起，`Esc` 关闭，方向键选择，回车打开。面板内按知识库、文档、内容片段分组，并提供「查看全部结果」进入 `/search`。
5. 知识库分类树属于知识库列表页的页内左栏，不放在应用导航中。应用导航在所有路由下保持一致。
6. 当前用户、账户设置、主题切换和退出登录收纳在导航底部的账户菜单中。
7. `>= 1280px` 使用完整导航，`981–1279px` 使用紧凑导航，`<= 980px` 使用导航抽屉，`<= 680px` 使用 16px 内容边距和移动端触控尺寸。
8. 任一断点不得出现整页横向滚动；导航抽屉打开时锁定背景滚动并约束焦点，Escape 关闭后恢复触发按钮焦点。
9. 支持浅色、深色和跟随系统三种主题，选择持久化在本地，首屏渲染前应用以避免闪烁。
10. 账户设置中的显示名称和头像地址上限按 Unicode 码点计数；新密码最小长度按 Unicode 码点、最大长度按 UTF-8 字节计数，不得使用 JavaScript `string.length` 或 HTML `maxLength` 代替。

## 登录页

1. 用户名和密码使用可见标签。
2. 支持显示/隐藏密码。
3. 提交期间禁用字段和按钮，避免重复登录请求。
4. 登录失败展示后端 `message`，并把焦点移动到错误摘要。
5. 字段级校验错误通过 `aria-describedby` 关联到输入框，并使用 `role="alert"` 播报。
6. 密码原值不得 trim；只有真正的空字符串才视为未填写，并在提交前按 UTF-8 字节拒绝超过后端 `account.maxPasswordBytes` 的输入。

验收：

~~~text
登录成功后保存 token
跳转到 /home
登录失败显示后端 message
全流程可用键盘完成
~~~

## 首页

1. 首屏是一个提问入口，提交后带 `?q=` 进入 `/chat`。
2. 「需要处理」区域仅在存在失败或处理中的文档时出现，每一项都可点击进入对应的筛选结果。
3. 会话、知识库和文档的最新动态合并为一条时间线，不拆成多个并列面板。
4. 统计以单行内联数字呈现，不使用带装饰的统计卡片。
5. 各区域独立加载；单个接口失败不得清空其他成功区域，并提供局部重试。
6. 加载时使用预留空间的 Skeleton；不伪造后端状态。

## 知识库列表页

1. 页面为两栏：左栏是分类树，右栏是工具栏、计数条、列表和分页。
2. 分类树只负责筛选和展开。新建、编辑、排序、删除通过分类栏的「管理分类」开关就地启用，不使用抽屉套对话框的层叠结构。
3. 范围（全部、我创建的、我管理的、收藏、最近浏览）、标签、可见性、排序、搜索关键词和分页全部写入 URL，使筛选结果可分享、可通过前进后退还原。
4. 视图模式（列表 / 卡片）和分类展开状态是本地显示偏好，保存在 localStorage 并立即生效。它们同时以「不阻塞、不报错」的方式后台同步到 `PUT /knowledge-bases/workspace-preference`，同步失败不得影响交互或提示用户。
5. **任何写操作只允许禁用它自己影响的控件。** 收藏、删除、移动单个知识库时，只禁用该行的操作；筛选、排序、分页、视图切换和导航在任何时候都必须保持可用。
6. 表格列为：选择、名称（含描述、标签、可见性图标）、状态、文档数、更新时间、操作。可见性和更新人不占用独立列。
7. 收藏保留为直接图标操作；编辑、移动到分类、删除收纳到每项的更多菜单。更多菜单支持方向键、Home、End 和 Escape，并在关闭后恢复触发器焦点。
8. 计数条展示知识库总数、处理中数量和存在失败数量，可点击作为筛选器。
9. 单项移动使用轻量 Dialog 并复用批量移动 API；请求失败保留 Dialog 和用户选择。
10. 删除前必须使用统一确认框，删除失败保留确认框并在其中展示错误。
11. 新建和编辑共用同一个对话框，不使用「新建走对话框、编辑走抽屉」的双形态。
12. 回收站和标签管理入口收纳在工具栏的更多菜单中。
13. 分页器展示首页和末页，中间用省略号收拢，让用户可判断列表深度。

可问答状态由列表聚合计数推导，优先级为：失败 > 处理中 > 可问答 > 暂无文档。旧后端缺少聚合字段但 `documentCount > 0` 时保守展示「处理中」。

## 权限与能力

界面按知识库响应里的 `effectiveRole` 与 `capabilities` 决定入口可见性，矩阵见
`docs/04-api-design.md`。三条约束：

1. **这是展示层，不是授权。** 服务端每个请求都会重新判定，前端漏判只会出现一个点了报 403
   的按钮。
2. **两个字段都可选。** 服务端没有返回时按「未知」处理，控件照常显示交由服务端拒绝，不要
   把界面变成只读；角色是无法识别的值则一律拒绝。方向刻意不对称。
3. **能力永远拿不到的入口移除，不禁用。** 灰掉的菜单项会让用户去找并不存在的开关。批量操作
   是 all-or-nothing，所选资源里有一个不可写就整体不可用，并说明原因。

不随能力隐藏的两处：收藏（写的是调用者自己的书签）和检索配置的取值（只读可见）。
问答相关入口不做能力筛选：`chat.use`、`chat.export`、`feedback.write` 都是 viewer 级，
可见的知识库必然都允许，加筛选是永远不生效的死代码。

客户端读取集中在 `frontend/src/utils/access.ts` 一个入口，不在各页面重复判断。

## 知识库详情页

1. 知识库上下文提供「概览、文档、设置」三个入口，当前入口使用 `aria-current="page"` 标识。
2. 「基于此知识库提问」是常驻主操作，在三个子页都可见，进入 `/chat?knowledgeBaseId=:id`，不提前创建空会话。
3. 概览展示文档处理状态、最近文档、基础信息和标签。三个处理状态数字均可点击，进入文档页并带上对应的状态筛选。
4. 文档使用 `/knowledge-bases/:id/documents`，与全局文档页由同一组件渲染。
5. 设置承载检索配置、成员权限和检索测试。
6. **检索配置是可编辑表单**，保存走 `PUT /knowledge-bases/:id`。前端从 `GET /system/capabilities` 读取 `vectorTopN` / `rerankTopK` 上限，并继续保证 `rerankTopK` 不超过 `vectorTopN`、`scoreThreshold ∈ [0,1]`；服务端校验仍为最终权威。
7. 成员权限仅在进入设置时加载，加载完成前不得展示可写控件；离开设置后应使未完成的权限搜索请求失效。
   成员面板需要 `members.read`（manager 起），不满足时整块不渲染——它的第一个请求只会返回 403。
   检索配置在没有 `kb.write` 时保持只读可见：这些值解释了一个回答为什么引用了这些内容。
8. 检索测试只在用户提交问题时请求；开启调试信息后展示后端返回的真实 debug 数据，不得由前端推测或伪造。

默认 `retrievalConfig`：

~~~json
{
  "vectorTopN": 30,
  "rerankTopK": 5,
  "scoreThreshold": 0.3,
  "enableRerank": true
}
~~~

## 文档管理页

`/documents` 与 `/knowledge-bases/:id/documents` **由同一个组件渲染**，差别只有外壳和作用域：前者是全局台账，后者嵌在知识库上下文中并把知识库筛选钉死。

1. 两个路由的数据源使用同一查询面：`GET /documents` 与 `GET /knowledge-bases/:id/documents` 支持相同的 `q`、`status`、`fileType`、`sort`、`page`、`pageSize`，后者只把 `knowledgeBaseId` 固定为路径值。筛选、排序和分页必须由服务端执行，不得把全量结果拉到浏览器再过滤。
2. 搜索、知识库、状态、类型、排序和分页写入 URL。
3. 首要摘要为「文档总数、可用于问答、处理中、失败」的单行计数条，每一项都是筛选开关。解析、切分、向量化等阶段只在文档行或详情中按需展示。
4. 表格列为：选择、文件名、知识库（仅全局台账）、状态、大小、更新时间、操作。**不设常驻的「处理提示」列**；失败原因显示在该行状态单元格内，仅失败行可见。
5. 两个路由复用同一个导入 Dialog；知识库页固定目标，全局页在 Dialog 内选择目标。选择文件后先展示待导入清单，用户确认后才上传。
6. 支持选择或拖放多个 `txt`、`md`、`pdf` 文件。按清单逐个调用单文件上传 API，逐项展示待上传、上传中、已上传和上传失败；上传中使用 XHR 的 `loaded / total` 字节事件展示逐文件真实传输百分比。部分失败时保留清单，并只重试失败项。
7. 客户端在上传前校验扩展名、空文件和默认 50 MiB 单文件上限；服务端校验仍为最终权威。上传期间禁止重复提交和关闭 Dialog。
8. 上传期间提供明确的「停止上传」操作，使用 `AbortSignal` 中止当前 XHR。上传接口没有幂等键，中止时当前请求可能已由服务端提交，因此当前项必须标为结果待确认并刷新文档列表，不得在同一批次直接重试；尚未开始的文件保持待上传，不得继续发起后续请求。用户确认文档未创建后，才可重新选择该文件上传。
9. 已选择文件后关闭 Dialog 必须先确认放弃待导入清单；上传完成后的自动关闭不得重复确认。
10. 存在未完成文档时每 3 秒刷新；全部为 `completed`、`failed` 或 `jobStatus=cancelled` 后停止轮询。**轮询失败必须静默**，不得覆盖用户正在阅读的错误，也不得把列表替换成错误态。
11. 列表和详情展示 `jobStatus`、`progress`、`stage`、`retryCount/maxRetries` 和 `nextRetryAt`；阶段和任务状态使用中文用户文案，`jobStatus=cancelled` 必须显示“已取消”并使用中性状态色，不能显示成“处理失败”。旧后端缺少这些字段时按文档 `status` 推导兼容进度。
12. 上传传输进度与上传后的解析、切片、Embedding 处理进度是两套独立状态；两类进度条都必须保留 `role="progressbar"`、可访问名称和当前值。
13. `failed` 必须作为独立失败状态展示，不得显示为 100% 完成；旧后端缺少进度字段时失败兼容进度为 0。错误提示必须说明恢复方式。取消任务保留已完成进度并提供重新处理，不得使用失败错误样式误导用户。
14. 写操作成功但列表刷新失败时，提示必须明确区分「操作成功」和「刷新失败」，不能诱导用户重复写操作。
15. 文档详情抽屉在 `?chunkId=` 指向的文档不属于当前知识库作用域时必须拒绝展示，而不是静默显示越界内容。

后端状态：

~~~text
uploaded
parsing
chunking
embedding
completed
failed
~~~

## AI 问答页

`/chat` 是草稿状态，`/chat/:sessionId` 是具体会话。两者是同一个页面，选择知识库并提问的过程中不切换屏幕。

1. 页面为两栏：左栏是知识库选择器与会话列表，右栏是消息线程与输入框。会话列表按今天 / 昨天 / 最近 7 天 / 更早分组，并使用服务端分页；仍有下一页时提供「加载更多会话」，追加结果不得替换已加载分组，加载失败只在该控件局部提示并可重试。直接打开归档会话深链时，侧栏范围同步为「已归档」。`<= 1080px` 时左栏变为可唤出的抽屉。
2. `/chat` 无消息时展示知识库启动器，承担原独立落地页的职责。首次提交问题时才创建会话，不得仅因浏览入口就创建空会话。
3. 输入框自动增高，`Enter` 发送、`Shift+Enter` 换行，输入法组合期间不触发发送。禁用时必须说明原因。既然 Enter 就是发送，手机键盘也要这么显示：`enterKeyHint="send"`。`Shift+Enter` 是硬件键盘的动作，旁边那行提示在 680px 以下本来就是隐藏的。
4. 会话标题就地编辑，不在标题栏常驻输入框和保存按钮。归档、导出和删除收纳在顶栏的会话操作菜单中；导出下载 Markdown。删除是软删除，会话和消息进入聊天回收站并可在永久删除前恢复，确认文案不得暗示消息已立即清除。
5. assistant 回答必须展示真实 citations；无引用时展示「当前知识库中未找到足够依据。」
6. citations 至少展示 `filename`、`pageNumber`、`content`、`vectorScore` 和 `rerankScore`。来源以每条回答下方的可展开列表呈现，不作为需要单独打开的第三栏。来源卡默认展示短摘录，长原文按需展开；向量分和精排分收纳在「检索详情」中，`rerankScore=null` 明确展示为「无精排分」。
7. assistant 正文中的合法 `[source:n]` 或 `[source:n,m]` 标记转换为可点击来源角标，仅当整组编号都对应本条回答的 citations 时生效；组内重复编号只展示一次，超长分组以及含无效或越界编号的标记整组保留原文。点击后展开来源列表并高亮对应条目。
8. Rerank 降级只在后端返回 `rerankFallback.used` 时提示，不得由前端推测。
9. 每条 assistant 回答提供「有帮助 / 没有帮助」二选一反馈控件，当前评价使用 `aria-pressed` 表达并从 `message.feedback` 恢复。保存期间只禁用该条回答的反馈控件；成功后局部更新消息，失败保留原状态并提示，重复选择按后端覆盖语义处理。
10. 生成期间提供「停止生成」操作并中止当前 SSE。主动停止仍先按原 `clientRequestId` 对账，不能在结果未知时宣称服务端未提交；确认未提交后可保留已收到的 delta/citations 作为未落库临时内容，并恢复继续提问。服务端在生成完成后、落库前必须再次检查请求 context，避免已取消请求进入持久化事务。
11. 只有用户停留在消息区底部附近时才随 delta 自动滚动；用户主动向上查看历史后，后续 token 不得强制拉到底部。
12. user 消息提供复制和编辑操作；assistant 消息提供复制，只有最新 assistant 回答提供重新生成。所有图标按钮必须有可访问名称，复制成功和失败都要有明确反馈。
13. 编辑 user 消息时在原气泡内显示多行输入框，支持 `Escape` 取消、`Ctrl/Cmd+Enter` 保存并重新生成。提交期间禁用重复操作；成功后替换目标及其后的消息，失败保留编辑草稿和原会话内容。

### 未确认写操作的处理

发送和重新生成都是非幂等写操作，网络结果未知时的处理规则如下。**这些规则约束行为，不约束措辞**：

1. 每次首次发送生成 UUID `clientRequestId`；显式重发必须复用原 ID，不得按消息数量或文本相等推测。
2. 结果未知时持久化 pending request，跨刷新按消息的 `clientRequestId` 对账。
3. **前端必须先自动对账两次（约 2 秒和 5 秒后）**，再考虑打扰用户。自动对账期间展示的是进行中的状态，不是需要用户决策的警告。
4. 自动对账仍未发现该消息时，才提供「再检查一次」和「确认重新发送」，且必须由用户显式确认才能再次发起写操作。
5. 只有明确的业务失败（4xx，或 `CHAT_COMPLETION_FAILED`、`RERANK_FAILED`）才允许直接重试；网络中断和未分类 5xx 一律走对账路径。
6. 重新生成失败或待确认的状态必须显示在对应 assistant 消息内。若浏览器无法持久化保护状态，则不得发起写操作。
7. 重新生成成功后直接使用接口返回的 `message` 更新线程；不得因后续列表刷新失败将已成功的写操作误报为失败。
8. 模型或检索错误展示中文业务提示，不直接显示 Provider 原始错误。
9. 编辑消息同样持久化原 `clientRequestId`。响应丢失时先按该 ID 读取消息列表对账；已提交则采用服务端消息，不得使用新 ID 重复生成。

## 全局搜索页

1. 关键词、结果类型和分页分别保存在 URL 的 `q`、`type`、`page`、`pageSize` 参数。
2. 全部、知识库、文档和内容片段筛选由服务端执行；切换类型或查询时重置到第一页，刷新和前进/后退后状态不丢失。
3. 输入停止 300ms 后以 replace 模式同步 `q`，显式提交立即同步；查询、类型或分页变化时中止过期请求，并防止忽略 AbortSignal 的旧 Promise 覆盖新结果。
4. `type=all` 时结果按类型分组展示。
5. 使用服务端 `total` 展示真实总数与前后翻页，不得用当前页 items 推测各类型总数。
6. 关键词高亮只渲染服务端返回的 `highlights`，偏移量按 UTF-16 code unit 解释；不得再由前端自行做子串匹配。
7. 明确展示加载、空结果、错误和局部重试状态，并通过 `role="status"` 播报搜索状态。
8. 存在有效查询时提供「导出 CSV」，参数必须复用当前 `q` 和 `type`，不受当前分页限制；导出期间只禁用导出按钮，失败不得清空搜索结果。超过 5000 条时展示后端 `EXPORT_TOO_LARGE` 的用户消息。
9. 搜索建议来自 `GET /search/suggest`，只给标题级结果（知识库、文档），是「已经知道要找哪一个」时越过结果页的快捷方式，不是结果页的替代：内容片段只在结果页出现，否则两个视图互相抢。按 ARIA 1.2 combobox 实现——listbox 是 input 的兄弟节点，焦点全程留在输入框，当前项由 `aria-activedescendant` 指示；方向键不得移动焦点，否则用户无法继续输入。打开列表不预选任何项，刚输入完按 Enter 表示「搜我输入的内容」。建议请求失败静默处理，下面的完整搜索会报告真正的错误。建议列表刻意不加 live region：combobox 模式下读屏已经在念当前项，再播报数量会和结果页的 `role="status"` 互相打断。
10. 无结果时的建议必须与后端的匹配方式一致。`GlobalSearchRepository` 走 `LOWER(column) LIKE '%query%'`——单次小写子串匹配，不分词。因此空格、引号和 `+ - | * ~` 都是字面字符，最有用的建议是拆短或去掉符号；「换一种大小写」是错的（查询本来就不区分大小写）。建议按证据强弱排序，只有「其他类型下确实有结果」是被观察到的事实，其余都是推断；无法确定时退回通用文案，不给自信的错建议。刻意不为空结果再发一次请求做「猜你想搜」。

## 标签管理页

1. 列表支持名称筛选和移动端字段标注卡片布局。
2. 新建和编辑在共享 Dialog 中完成；失败后保留输入并展示后端 `message`。
3. 创建和更新成功后局部更新列表，不重新加载整表。
4. 删除前确认；删除失败时保留原行和确认框，并在确认框内展示后端错误。
5. 「使用量」列展示后端 `knowledgeBaseCount`；兼容旧响应缺少该字段时才显示 `—`。
6. 成功操作通过全局 Toast 通知。

## 全局反馈与可访问性

1. Button、IconButton、Field、Badge、Table、Pagination、Drawer、Popover、EmptyState、ErrorState、LoadingSkeleton、Dialog 和 Toast 使用统一语义样式，全部定义在 `src/styles/primitives.css`。
2. 图标按钮必须同时提供 `aria-label` 与 tooltip，不使用字符或英文占位图标。
3. 搜索类输入框的移动键盘提示由 `SearchInput` 统一给默认值，不在每个调用点重复：`enterKeyHint="search"`（手机上显示搜索键而不是换行键），以及 `autoCapitalize` / `autoCorrect` / `autoComplete` 全关——自动大写和纠错会和标识符、文件名打架，浏览器的自动填充下拉还会盖住建议列表。默认值写在展开之前，调用点仍可覆盖。
4. 表单字段的提示和错误必须通过 `aria-describedby` 关联到控件；错误同时设置 `aria-invalid` 并使用 `role="alert"` 播报。
5. Dialog 与 Drawer 支持 Escape、焦点约束、背景滚动锁定和焦点恢复，并支持嵌套。
6. 所有交互控件保留明显 `:focus-visible`；关键移动端触控目标不低于 44px。触控尺寸只有一个归口：`styles/touch.css`，断点是 `@media (max-width: 980px)`，用宽度而不是 `(pointer: coarse)`——二合一笔记本接触控屏时也报 coarse，但用户手上是触摸板。装文字的控件只写 `min-height`，不写 `height`，内容本来就更高的控件不能被压小；方形图标按钮是例外，两个方向都写，点击区域要和看得见的圆形一致。页面样式表不得再自行定义触控尺寸；`touch.css` 必须最后引入，靠顺序而不是 `!important` 取胜。悬停才显示的行内操作在这个断点必须常驻可见，没有指针就没有悬停。
7. 危险操作统一使用 `ConfirmDialog`；失败保留在确认框内，成功通过全局 Toast 通知，不使用原生 `window.confirm`。
8. 支持 `prefers-reduced-motion`；成功、警告和危险状态不能只依赖颜色表达。
9. 知识库、分类、标签等编辑表单以及待导入文件清单存在未保存内容时，取消、Escape 或遮罩关闭必须先确认；刷新或关闭标签页时使用 `beforeunload` 保护。
10. 全局 Toast 在 Dialog 或 Drawer 打开期间仍须可见并可被辅助技术播报，但不得成为可交互的焦点目标。
11. 整个应用只有一个 `<main>` landmark，由 `AppShell` 拥有。
12. 一个页面同时只能有一个 polite live region 在描述同一件事。多个 polite 区域会互相打断，这正是「克制的播报」要排除的情况；测试里 `getByRole('status')` 在存在多个时直接抛错，这个抛错本身就是断言。live region 必须常驻在 DOM 里、只改内容：和文字一起挂载的区域播报不可靠。流式回答的阶段播报见 `useStreamAnnouncement`——检索、生成、已停止、完成各说一次，失败不说，因为线程里的失败提示是 `role="alert"`（assertive，自己会播报），再说一遍就是重复。
13. 焦点归还是每一条关闭路径的义务，不是可选项。视觉上看不出焦点丢失，所以每条路径都要有测试锁住：
    - Dialog、Drawer 统一走 `useModalFocus`（堆叠、焦点约束、背景 `inert` / `aria-hidden`、Escape、Tab 循环）。触发元素已经不存在时退到 `[data-modal-focus-fallback]`，该标记必须至少有一个在桌面端也渲染的控件上。
    - portal 浮层（Popover、OverflowMenu）用 Tab 关闭时必须 `preventDefault` 再手动把焦点放回触发器。不能放默认行为走：浏览器计算 Tab 目标时 React 还没卸载面板，焦点会进入即将消失的面板，最后落到 `body`。代价是多按一次 Tab，换来的是永不丢焦点。
    - 浮层打开时必须主动把焦点移进面板。portal 挂在 `body` 末尾，Tab 会跳过它，不移进去等于键盘用户根本到不了，Escape 也收不到 keydown。
    - 点击外部关闭属于「用户已经去了别处」，不得把焦点抢回触发器；只有键盘关闭才归还。
    - 就地编辑（InlineEdit）进入编辑要显式 `focus()`，不能只靠 `select()`；保存、取消、Escape 三条退出路径都要回到触发按钮。
    - 列表行删除后焦点落到相邻行的同一个控件（末行则落到前一行），用 `useRowFocusAfterRemoval`：相邻行在删除**开始**时选定（那时行还在），焦点在 effect 里移动（对话框在自己的 cleanup 里归还焦点，React 先跑完 cleanup 再跑 effect）。只剩一行时交给上面的 fallback。

## 样式约束

~~~text
src/styles/
  tokens.css        设计令牌，唯一允许出现颜色和尺寸字面量的地方，含深色模式
  reset.css
  primitives.css    跨页复用的组件样式
  app-shell.css     导航、顶栏、命令面板
  pages/*.css       每个页面一个文件
  touch.css         移动端触控尺寸，必须最后引入
~~~

1. `pages/*.css` 之间不得互相引用选择器；任何跨页复用必须提升到 `primitives.css`。
2. 页面样式表不得重新定义 `primitives.css` 中的 `.ui-*` 选择器。
3. 层级由 1px 边框表达，投影只用于浮层（Dialog、Drawer、Popover、Toast、命令面板）。
4. 强调色只有一个，状态色只用于表达状态，不用于装饰。
5. 字号只使用 tokens 中的六级尺度。
6. 竖向视口尺寸一律用 `dvh`，不用裸 `vh`：移动端地址栏和软键盘会压缩可视高度，`vh` 不跟着变，结果是内容被挤而留白不动。横向的 `vw` 不受这两者影响，不在此列。`styles/viewport-units.test.ts` 守住这条。

## API 与代码约束

1. token 保存在 token store；API 请求统一注入 `Authorization: Bearer <token>`。
2. 401 时清理 token 并跳转登录页；错误反馈优先使用后端 `message`。
3. 页面级筛选优先写入 URL；本地显示偏好写入 localStorage；可过期请求通过 `AbortSignal` 取消。
4. 路由页面使用 `React.lazy` 分包；`App.tsx` 只承载 Outlet，不堆叠页面实现。新增或删除路由页面时必须同步更新 `scripts/verify-route-chunks.mjs`。
5. `resources.ts` 保持兼容导出；API 字段使用 camelCase，不伪造文档状态、检索分数、Rerank 状态或 citations。
6. 时间、字节、数字和分数的格式化统一使用 `src/utils/format.ts`，不在页面内重复实现。
7. 并发写操作使用 `useEntityMutation` 按实体 id 跟踪，禁止引入页面级互斥锁。
