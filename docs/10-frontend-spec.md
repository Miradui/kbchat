# 前端规范

## 视觉与布局（2026-10-19）

采用用户认可的 Perplexity 风格，以暖白、灰绿、单侧导航和居中提问区组织内容；知识库封面保留轻量的 Craft 风格色块。新对话、已有会话、来源预览和资料管理使用同一组明暗主题变量。实现与验收见 [前端视觉改版](34-perplexity-frontend.md)。

## 六项知识工作流（2026-10-19）

- 新聊天可选择 1–20 份已处理文档（最多 5 库），详情与列表勾选项均有提问入口。会话显示固定文档范围；切换范围创建新会话。范围失效提示重新选择，不扩大检索。
- 草稿按账号和会话/新会话范围保存在本浏览器，最多 50 份、每份 32000 字符、30 天；超长内容仅内存保留，存储不可用不阻止输入。刷新/切会话恢复，收到成功回执且内容仍匹配才清除；退出清理命名空间，不跨设备同步。
- 引用原文面板展示有效新版或尚未发布提示，可打开已有版本对比。按当前有效资料提问带齐本回答全部引用的有效版本并预填原问题；任一不可读时不提供缩小范围的快捷动作。旧回答保持。
- TXT/Markdown 详情提供原始正文编辑与安全预览，1 MiB 上限；保存新版本、失败保留输入、关闭确认未保存修改，成功后可进入新版本。
- PDF 有已发布 OCR 页且具备写入/下载能力时提供校对入口。左右对照 PDF 物理页与识别文字，页选择保持同步且保留各页修改；只提交改动 OCR 页，原生页不编辑。校对版本的引用和导出区分“人工校对 OCR”，无坐标不猜测高亮。
- 质量反馈页可选择单库运营、我的全部、自动、固定多库、指定文档。个人问题的“跟进”保存备注、补充资料关联、测试用例及最近复测；去补资料或创建用例前先保存记录，失败留在原弹窗。复测保持原范围与请求配置，手动标记解决，可重新打开。评测能力沿用 quality.read，不提高成员权限。
- 评测列表和结果显示来源范围；默认及“选择前 20 题”只选同范围用例，取消选择后可切换另一组，避免把私人跨库和共享单库问题混入一次运行。

前端使用 React，目标是克制、清晰的企业级 AI 知识库与问答产品。MVP 不做营销首页，不引入大型 UI 框架。

页面行为以本文件为准，接口、字段和权限见 `04-api-design.md`。发现接口与页面需求不一致时，先核对现行合同；需要调整接口时同步更新 API 规范，尚未完成的工作记录在 `12-handoff.md`。

### 兼容重定向

以下入口在历史版本中存在，必须继续可用：

| 旧地址 | 行为 |
|--------|------|
| `/chat/new?knowledgeBaseId=X` | `replace` 到 `/chat?knowledgeBaseId=X`，保留全部 query |
| `/knowledge-bases/:id?tab=overview` | `replace` 到 `/knowledge-bases/:id` |
| `/knowledge-bases/:id?tab=settings` | `replace` 到 `/knowledge-bases/:id/settings` |
| `/knowledge-bases/:id?tab=qa` | `replace` 到 `/chat?knowledgeBaseId=:id` |

### 深链接合同

以下 query 参数被引用卡片、全局搜索和跨页跳转依赖，不得更改语义：

~~~text
/knowledge-bases?intent=create              打开新建知识库对话框并消费该参数
/documents?intent=upload                   打开全局导入对话框并消费该参数
/documents?status=processing                展示全部处理中文档
/knowledge-bases/:id/documents?intent=upload 打开导入对话框并消费该参数
/knowledge-bases/:id/documents?documentId=   打开文档详情抽屉
/knowledge-bases/:id/documents?documentId=&chunkId=  定位到指定内容片段
/chat?knowledgeBaseId=                       以该知识库开始一个草稿会话
/chat?q=                                     预填充输入框并消费该参数
/search?q=&type=&page=&pageSize=             全局搜索状态
~~~

## 全局应用外壳

1. 左侧导航为每个区域提供一级入口，依次为首页、AI 问答、质量运营、知识库、文档、标签，以及仅当前系统管理员可见的系统诊断、用户管理。各页使用相同的紧凑行高、间距和顺序，不根据路由增删分组标题；切换页面只改变对应入口的选中状态。不得把某个区域映射到另一个区域的高亮项。
2. 不展示不属于 MVP 的功能占位项。
3. 顶栏承载面包屑、命令面板入口和页面级操作；正文使用清晰的页面标题与简短说明，列表页的主操作放在标题区，筛选工具栏聚焦筛选。知识库、文档、搜索页复用 `PageHeading`；完整导航宽 236px，顶栏高 64px，列表内容最大宽 1200px，通过对齐与分隔线组织，减少嵌套面板。
4. 全局搜索通过命令面板进入，`⌘K` / `Ctrl+K` 唤起，`Esc` 关闭，方向键选择，回车打开。面板内按知识库、文档、内容片段分组，并提供「查看全部结果」进入 `/search`。
5. 知识库分类树属于知识库列表页的页内左栏，不放在应用导航中。受保护路由共用一个常驻的应用外壳：切换页面只替换内容区，导航、账户菜单和顶栏骨架不重建；页面挂载时注册自己的面包屑、顶栏操作和内容留白，页面分包未加载时先按路径推导选中项。最近对话只属于 AI 问答页，位于消息区左侧，不进入全局导航；`> 1080px` 时为可折叠的页内栏，`<= 1080px` 时为模态抽屉。列表按账号、知识库筛选和活跃/归档状态共享已加载分页，重新进入问答页时复用数据，恢复该组合下的滚动位置，并沿用上次的折叠状态。数据默认保鲜 60 秒，重新进入过期视图时后台更新；重命名、归档、删除和权限失效清理同步更新相关缓存，账号切换或退出时清空。
6. 当前用户、账户设置、主题切换和退出登录收纳在导航底部的账户菜单中。切页首帧复用当前登录身份已确认的账号信息，避免管理员入口先消失再出现；账号切换不能沿用旧角色。
7. `>= 1280px` 使用完整导航，`981–1279px` 使用紧凑导航，`<= 980px` 使用导航抽屉，`<= 680px` 使用 16px 内容边距和移动端触控尺寸。
8. 任一断点不得出现整页横向滚动；导航抽屉打开时锁定背景滚动并约束焦点，Escape 关闭后恢复触发按钮焦点。
9. 支持浅色、深色和跟随系统三种主题，选择持久化在本地，首屏渲染前应用以避免闪烁。
   三种模式统一使用灰绿强调色：浅色为 `#356f6d`，深色为 `#b4d0c2`；主背景分别为暖白 `#fcfcfa` 和深灰绿 `#1b211f`。主要按钮使用独立的深墨色/浅色动作变量，状态色另行表达成功、警告和错误。桌面正文 14px、主要阅读内容 16px、页面标题 28px、启动器标题 36px，长文阅读行高 1.85；沿用系统字体栈，不加载远程字体。
10. 账户设置分为个人资料和修改密码，切换时保留草稿；加载完成前不可编辑，读取失败可重试。显示名称上限按 Unicode 码点计数；新密码最小长度按 Unicode 码点、最大长度按 UTF-8 字节计数，不得使用 JavaScript `string.length` 或 HTML `maxLength` 代替。
11. 头像支持选取 PNG/JPEG（最大 2 MiB、4096×4096），在浏览器按图片方向居中裁剪并预览；显式保存后上传。失败保留预览，取消、更换或关闭释放 Blob URL。上传、移除和资料/密码写操作互斥，保存中不可关闭或重复提交，迟到响应不得修改新打开的弹窗或另一个账户。
12. 名称保存省略 `avatarUrl`，避免覆盖新头像。导航、账户与成员列表通过鉴权请求显示托管头像，外链地址不附带 token；加载失败回退首字。账户 UI 以图片选择取代原始 URL 输入，API 继续兼容外部头像地址。
13. 产品品牌使用中文「知汇」，导航副标题为「知识管理 · 智能问答」。导航、登录页和浏览器标签统一使用叠页对话图标；页面 SVG 随主题继承颜色，favicon 支持系统明暗配色。品牌名称、登录页品牌文案及浏览器标题均使用中文。品牌区域点击返回首页，提供完整的键盘焦点轮廓；明暗主题保持一致的标识与清晰对比。

## 登录页

1. 用户名和密码使用可见标签。
2. 支持显示/隐藏密码。
3. 提交期间禁用字段和按钮，避免重复登录请求。
4. 登录失败展示后端 `message`，并把焦点移动到错误摘要。
5. 字段级校验错误通过 `aria-describedby` 关联到输入框，并使用 `role="alert"` 播报。
6. 密码原值不得 trim；只有真正的空字符串才视为未填写，并在提交前按 UTF-8 字节拒绝超过后端 `account.maxPasswordBytes` 的输入。
7. 桌面布局分为深绿品牌介绍和独立登录表单两区，品牌区以「汇集文档 → 检索知识 → 获得答案」说明产品用途。表单保留清晰标题、可见标签和账户获取说明；小屏优先显示登录表单。
8. `429 RATE_LIMITED` 在表单错误摘要中显示“请求过于频繁，请 N 秒后再试”，秒数优先取 `Retry-After`，缺失时取 `details.retryAfter`；不进入全局 Toast。按收到响应时的截止时间动态倒数，标签页恢复时校准，归零显示“等待已结束，可以重试。”；没有合法秒数时显示“请稍后再试”。不自动重发，不因倒计时新增按钮锁定；逐秒文字使用 `aria-live="off"`，避免重复强制播报。

验收：

~~~text
登录成功后保存 token
跳转到 /home
登录失败显示后端 message
全流程可用键盘完成
~~~

## 首页

1. 首屏为居中的提问入口，输入容器最大宽 750px；提交后带 `?q=` 进入 `/chat`。
2. 「需要处理」区域在加载、读取失败或存在失败/处理中文档时出现；处理中与失败文档分别显示读取错误和重试入口，不能把加载失败展示成无需处理。重试不重载最近动态。每一项状态提醒均可点击进入对应的筛选结果，已取消的任务不作为处理失败提醒。
3. 会话、知识库和文档的最新动态合并为一条时间线，不拆成多个并列面板。
4. 统计以单行内联数字呈现，不使用带装饰的统计卡片。
5. 各区域独立加载；单个接口失败不得清空其他成功区域，并提供局部重试。
6. 加载时使用预留空间的 Skeleton；不伪造后端状态。
7. 提问框下方提供带简短说明的新建知识库、导入文档和查看会话入口；导入直接打开 `/documents?intent=upload`，不要求先进入某个知识库。

## 知识库列表页

1. 页面标题、说明和新建操作位于顶部；下方为两栏：左栏是分类树，右栏是工具栏、计数条、列表和分页。
2. 分类树只负责筛选和展开。通过分类栏的「管理分类」开关就地启用管理模式，每行常驻一个更多菜单，收纳新增子分类、编辑、上移、下移和删除。操作按钮不得挤占名称空间或仅在悬停时可见；长名称以省略号截断并提供完整名称提示，数量独立显示。展开后显示本级数量，折叠后显示含子分类的数量。排序请求期间只禁用对应分类的上移、下移操作。
3. 范围（全部、我创建的、我管理的、收藏、最近浏览）、标签、可见性、排序、搜索关键词和分页全部写入 URL，使筛选结果可分享、可通过前进后退还原。
4. 视图模式（列表 / 卡片）和分类展开状态是本地显示偏好，保存在 localStorage 并立即生效。它们同时以「不阻塞、不报错」的方式后台同步到 `PUT /knowledge-bases/workspace-preference`，同步失败不得影响交互或提示用户。
5. **任何写操作只允许禁用它自己影响的控件。** 收藏、删除、移动单个知识库时，只禁用该行的操作；筛选、排序、分页、视图切换和导航在任何时候都必须保持可用。
6. 表格列为：选择、名称（含描述、标签、可见性图标）、状态、文档数、更新时间、操作。可见性和更新人不占用独立列。
7. 收藏保留为直接图标操作；编辑、移动到分类、删除收纳到每项的更多菜单。更多菜单支持方向键、Home、End 和 Escape，并在关闭后恢复触发器焦点。
8. 知识库计数条展示总数、处理中数量和存在失败数量，为静态概况；文档页计数条才是可点击的状态筛选器，两者使用不同的交互样式。
9. 单项移动使用轻量 Dialog 并复用批量移动 API；请求失败保留 Dialog 和用户选择。
10. 删除前必须使用统一确认框，删除失败保留确认框并在其中展示错误。
11. 新建和编辑共用同一个对话框，不使用「新建走对话框、编辑走抽屉」的双形态。
12. 回收站和标签管理入口收纳在工具栏的更多菜单中。
13. 分页器展示首页和末页，中间用省略号收拢，让用户可判断列表深度。
14. 卡片视图使用独立卡片承载名称、描述、状态和文档数，不再套一层列表面板。封面位于左上，勾选、收藏和更多操作在右侧，状态、文档数、更新时间和可见性在底部。选中项同时显示勾选框与主题强调背景、边框，不能只靠颜色表达选中状态。
15. 批量栏只展示收藏或取消收藏、移动到分类、管理标签、删除和取消选择。分类与标签选项在独立弹窗中设置；分类必须显式选择，标签可多选并支持添加、移除或替换，替换时说明原有其他标签将移除。失败保留选择，保存中阻止重复提交和关闭；选项加载失败可重试。
16. 两种视图均支持选择当前页及半选状态。取消选择和批量保存后将焦点归还知识库列表；取消弹窗则回到原操作按钮。
17. 知识库主图标采用带书脊的书本封面，卡片按资源 ID 稳定使用绿、砂、蓝三组柔和配色；封面色不代表状态或权限。私有/公开以独立小图标和文字展示，提示说明访问仍遵循知识库成员权限。
18. `<= 900px` 的分类区域默认折叠，标题显示当前分类并支持展开/收起；进入分类管理时展开。表格和卡片的独立复选框使用标签扩大点击区域，在 `<= 980px` 下至少 44×44px，勾选图形本身保持紧凑。

可问答状态由列表聚合计数推导，优先级为：失败 > 处理中 > 可问答 > 暂无文档。旧后端缺少聚合字段但 `documentCount > 0` 时保守展示「处理中」。

## 权限与能力

界面按知识库响应里的 `effectiveRole` 与 `capabilities` 决定入口可见性，矩阵见
`docs/04-api-design.md`。三条约束：

1. **这是展示层，不是授权。** 服务端每个请求都会重新判定，前端漏判只会出现一个点了报 403
   的按钮。
2. **两个字段都可选。** 服务端没有返回时按「未知」处理，控件照常显示交由服务端拒绝，不要
   把界面变成只读；角色是无法识别的值则一律拒绝。方向刻意不对称。
3. **能力永远拿不到的入口移除，不禁用。** 灰掉的菜单项会让用户去找并不存在的开关。批量操作
   是 all-or-nothing，所选资源里有一个不可写就整体不可用，并说明原因。

不随能力隐藏的两处：收藏（写的是调用者自己的书签）和检索配置的取值（只读可见）。
问答相关入口不做能力筛选：`chat.use`、`chat.export`、`feedback.write` 都是 viewer 级，
可见的知识库必然都允许，加筛选是永远不生效的死代码。

客户端读取集中在 `frontend/src/utils/access.ts` 一个入口，不在各页面重复判断。

## 知识库详情页

1. 知识库上下文提供「概览、文档、设置」三个入口，当前入口使用 `aria-current="page"` 标识。
2. 「基于此知识库提问」是常驻主操作，在三个子页都可见，进入 `/chat?knowledgeBaseId=:id`，不提前创建空会话。
3. 概览展示文档处理状态、最近文档、基础信息和标签。三个处理状态数字均可点击，进入文档页并带上对应的状态筛选。
4. 文档使用 `/knowledge-bases/:id/documents`，与全局文档页由同一组件渲染。
5. 设置承载检索配置、回答配置、成员权限和检索测试。
5b. 设置中的「文档版本检索」独立保存 `documentVersionPolicy`：全部版本 / 当前有效版本。说明新版处理失败或尚未完成时使用旧快照、重处理保留已发布内容、历史引用继续保留；作用于本库参与的单库/多库/自动检索。没有 `kb.write` 的用户只能查看；保存失败保留选择。保存此设置不提交或改变模型、回答及检索质量参数。
5a. **回答配置与检索配置并列**，同样走 `PUT /knowledge-bases/:id`。字段为系统提示补充（≤2000 字符）、回答语言（自动 / 中文 / English）、允许补充常识、回答模型与温度（0–1，留空用 Provider 默认）。模型下拉只列出 `GET /system/capabilities` 的 `chatModels`；列表为空时下拉禁用并说明未开放模型覆盖。两个表单互不覆盖：任一表单保存时都携带另一块的当前值，改名等入口不带配置块时服务端保留已存值。没有 `kb.write` 时只读可见。提示补充、语言、模型与温度只作用于手动单库会话；「允许补充常识」另外在多库与自动会话生效，且要求本轮引用到的每个库都开启。
6. **检索配置是可编辑表单**，保存走 `PUT /knowledge-bases/:id`。前端从 `GET /system/capabilities` 读取 `vectorTopN` / `rerankTopK` 上限，并继续保证 `rerankTopK` 不超过 `vectorTopN`、`scoreThreshold ∈ [0,1]`；服务端校验仍为最终权威。
7. 成员权限仅在进入设置时加载，加载完成前不得展示可写控件；离开设置后应使未完成的权限搜索请求失效。
   成员面板需要 `members.read`（manager 起），不满足时整块不渲染——它的第一个请求只会返回 403。
   检索配置在没有 `kb.write` 时保持只读可见：这些值解释了一个回答为什么引用了这些内容。
8. 检索测试只在用户提交问题时请求；开启调试信息后展示后端返回的真实 debug 数据，不得由前端推测或伪造。

默认 `retrievalConfig`：

~~~json
{
  "vectorTopN": 30,
  "rerankTopK": 5,
  "scoreThreshold": 0.3,
  "enableRerank": true
}
~~~

## 文档管理页

`/documents` 与 `/knowledge-bases/:id/documents` **由同一个组件渲染**，差别只有外壳和作用域：前者是全局台账，后者嵌在知识库上下文中并把知识库筛选钉死。

1. 两个路由的数据源使用同一查询面：`GET /documents` 与 `GET /knowledge-bases/:id/documents` 支持相同的 `q`、`status`、`fileType`、`sort`、`page`、`pageSize`，后者只把 `knowledgeBaseId` 固定为路径值。筛选、排序和分页必须由服务端执行，不得把全量结果拉到浏览器再过滤。
2. 搜索、知识库、状态、类型、排序和分页写入 URL。文件名输入即时显示，250ms 防抖后提交；清空和 Enter 立即提交且取消待执行计时，中文输入法组合期间不提交。筛选、翻页及前进后退立即应用已提交的 URL 状态并取消旧搜索草稿；查询变更重置页码。首次查询只发一次列表和一次 `GET /documents/counts`；统计仅随 q、knowledgeBaseId、fileType 改变，状态、排序及分页只更新列表。轮询及写后刷新一并更新统计，保留取消、迟到结果守卫及统计失败显示未知。知识库列表仍按搜索表单提交。
3. 首要摘要为「文档总数、可用于问答、处理中、失败」的单行计数条，每一项都是筛选开关。解析、切分、向量化等阶段只在文档行或详情中按需展示。
   「处理中」使用 `status=processing` 汇总上传、解析、切片和向量化阶段；展开后的阶段选择器可切换为具体阶段，并可回到「全部处理中」。
4. 表格列为：选择、文件名、知识库（仅全局台账）、状态、大小、更新时间、操作。**不设常驻的「处理提示」列**；失败原因显示在该行状态单元格内，仅失败行可见。
5. 两个路由复用同一个导入 Dialog；知识库页固定目标，全局页在 Dialog 内选择目标。选择文件后先展示待导入清单，用户确认后才上传。
6. 支持选择或拖放多个 `txt`、`md`、`pdf`、`docx`、`xlsx`、`csv` 文件，以及文件夹 / ZIP。按清单逐个调用单文件上传 API，逐项展示待上传、上传中、已上传和上传失败；上传中使用 XHR 的 `loaded / total` 字节事件展示逐文件真实传输百分比。部分失败时保留清单，并只重试失败项。DOCX 在列表和详情中使用独立文件类型图标，类型筛选沿用服务端返回的 `fileType`。
7. 客户端在上传前校验扩展名、空文件和默认 50 MiB 单文件上限；服务端校验仍为最终权威。上传期间禁止重复提交，可通过「后台继续」或关闭按钮收起窗口，在同一标签页内切换页面不会取消上传。
8. 每个文件或粘贴文本携带稳定 `requestId`。网络断连或未分类 5xx 后先查询上传凭据：已提交则使用返回文档并继续清单；尚无凭据则用同一 ID 自动重传一次，再次不确定时重新查询。查询也失败时暂停并保留清单，提供「恢复上传」，浏览器联网事件可自动继续。主动「停止上传」中止当前 XHR，保留请求 ID，之后只在用户恢复时核对并继续。替换和保留两份为新的明确选择分配新 ID，其重试保留 ID 与原选择；文档已删除/移动的凭据不得重新创建文档。权限拒绝不会自动重试。该功能为整文件重试，不是分片续传；切换应用页面不中断，刷新或关闭浏览器后仍需重新选择本地文件。
9. 「收起窗口」保留当前清单，不要求放弃确认；「取消」清空已选择清单前必须确认，已经上传的文档不受影响。上传全部成功后的自动关闭不得重复确认；存在重复文件选择或未确认结果时保留窗口与清单。
10. 存在未完成文档时每 3 秒刷新；全部为 `completed`、`failed` 或 `jobStatus=cancelled` 后停止轮询。**轮询失败必须静默**，不得覆盖用户正在阅读的错误，也不得把列表替换成错误态。
详情抽屉独立每 2 秒读取当前文档进度，完成、失败或取消后停止；临时读取失败保留界面并重试，403/404 清除原文件与片段。关闭或切换文档后忽略旧请求。重新处理保留不可变的原文件预览，完成后刷新片段，无需关闭抽屉或刷新页面。

11. 列表和详情展示 `jobStatus`、`progress`、`stage`、`retryCount/maxRetries` 和 `nextRetryAt`；阶段和任务状态使用中文用户文案，`jobStatus=cancelled` 必须显示“已取消”并使用中性状态色，不能显示成“处理失败”。旧后端缺少这些字段时按文档 `status` 推导兼容进度。
12. 上传传输进度与上传后的解析、切片、Embedding 处理进度是两套独立状态；两类进度条都必须保留 `role="progressbar"`、可访问名称和当前值。
13. `failed` 必须作为独立失败状态展示，不得显示为 100% 完成；旧后端缺少进度字段时失败兼容进度为 0。错误提示必须说明恢复方式。取消任务保留已完成进度并提供重新处理，不得使用失败错误样式误导用户。
14. 写操作成功但列表刷新失败时，提示必须明确区分「操作成功」和「刷新失败」，不能诱导用户重复写操作。
15. 文档详情抽屉在 `?chunkId=` 指向的文档不属于当前知识库作用域时必须拒绝展示，而不是静默显示越界内容。
    下载、重新处理、取消处理和删除按当前文档所属知识库的 capabilities 显示；权限未确认或查询失败时默认隐藏操作，保留可读取的正文与片段。没有 `document.download` 时不获取 PDF 原文件，展示可阅读下方片段的说明。
16. 标题和导入操作置于筛选栏上方，列表与标题共用内容宽度，筛选栏不额外包裹面板。文件名搜索明确标注“搜索文件名”。文档状态标签按内容宽度显示，进度条仍展示真实处理进度。
17. 导入队列由 `App` 内的 `DocumentImportProvider` 持有，独立于页面路由。同一时间保留一份本地导入清单；已有清单时，从其他页面再次导入会返回该清单。第一次提交后锁定目标知识库，重试、重复文件选择和切页不得改变目标。
18. 顶栏的「上传任务」在有任务时常驻，显示进行中或待处理数量。任务抽屉区分文件传输与文档处理，支持返回导入清单继续操作、查看文档、处理完成后开始提问，以及清除已结束的本地记录。清除记录不会删除文档。
19. 上传后按文档 ID 查询实际处理状态，每轮最多并发 3 个请求，约 2.5 秒继续下一轮；失败退避至最多 30 秒，403/404 暂停自动查询并提供手动重试。完成、最终失败或取消后停止查询；有待执行重试的任务继续跟踪。状态读取错误保留上次进度，不把读取失败当成处理失败。
20. 退出登录、鉴权失效或其他标签页切换账户时，中止本地文件传输和查询并清空本地任务，迟到结果不得进入新账户。已在服务端创建的文档继续由后端处理。
21. 当前能力限于同一浏览器标签页内的路由切换；刷新或关闭浏览器不支持文件断点续传。仍持有未完成文件时通过 `beforeunload` 提示；文件全部上传后不拦截离开，服务端处理状态仍可从文档列表查询。
22. 文档详情保留现有路由查询参数和抽屉，阅读抽屉上限 960px、窄屏使用视口宽度；不影响其他用途的抽屉。已完成进度压缩为一行，文本预览跟随抽屉连续滚动，不再限制为 340px 高的嵌套区域。
23. Markdown 默认排版阅读，支持标题、列表、表格、引用及代码，提供保留完整内容的等宽“原始文本”切换；TXT/DOCX 仍按纯文本显示。Markdown 不使用聊天引用插件，`[source: n]` 保留字面值；跳过原始 HTML、过滤危险链接，不加载文档图片，图片仅显示替代文本。
24. 预览和片段各自提供局部重试，不重载详情、另一分区或重置片段分页。详情读取失败提供“重新加载详情”。切换文档后丢弃旧结果。引用深链接等预览完成或失败后再滚动并聚焦片段，避免迟到正文将目标推离可视区；同一片段只自动定位一次。PDF 阅读区域预留固定高度，仍使用原查看器的翻页、缩放与权限保护。
25. PDF 详情在进度下方展示 `pdfTextSummary` 中未提取到文字的页数和物理页码，连续页合并为范围；超过 20 个页码时可展开查看。启用 OCR 后显示逐页进度、OCR 提取文字的页码及仍为空的页面；未启用、工具缺失、超时和识别失败提供对应建议，不把空白页断言为损坏。部分 OCR 失败明确说明本次结果尚未发布、旧片段仍保留。全空 PDF 的失败仍保留摘要；缺失旧摘要保持未知。重处理立即清除旧摘要，轮询刷新；只读成员可查看摘要，不因此获得下载权限。内容片段及聊天来源标注“OCR 识别文本”；原生 PDF 的普通阅读保持既有行为。

uploaded
parsing
chunking
embedding
completed
failed
~~~

## AI 问答页

`/chat` 是草稿状态，`/chat/:sessionId` 是具体会话。两者是同一个页面，选择知识库并提问的过程中不切换屏幕。

1. 桌面问答页在应用导航右侧显示独立的历史会话栏，栏内保留知识库筛选、搜索、收藏与笔记、活跃/归档切换和每项的更多操作；栏可收起，收起后由顶栏左侧的「打开会话列表」按钮恢复，并回到收起前的滚动位置，输入草稿不受影响。会话列表按今天 / 昨天 / 最近 7 天 / 更早分组，并使用服务端分页；仍有下一页时提供「加载更多会话」，追加结果不得替换已加载分组，加载失败只在该控件局部提示并可重试。已有分页在离开问答页后复用，迟到的旧列表请求不得撤销成功的修改或重新插入失效会话。直接打开归档会话深链时，侧栏范围同步为「已归档」。`<= 1080px` 时会话列表为可唤出的模态抽屉。
2. `/chat` 新草稿使用居中启动器，输入框紧接标题与说明，下面为提问建议和知识库范围卡片。桌面顶部面包屑显示「新对话」，不额外占用一行会话标题；窄屏保留标题和打开会话列表按钮。建议只向草稿追加问题，不覆盖已有内容或自动发送。首次提交问题时才创建会话，不得仅因浏览入口就创建空会话。
3. 输入框自动增高，`Enter` 发送、`Shift+Enter` 换行，输入法组合期间不触发发送。禁用时必须说明原因。既然 Enter 就是发送，手机键盘也要这么显示：`enterKeyHint="send"`。`Shift+Enter` 是硬件键盘的动作，旁边那行提示在 680px 以下本来就是隐藏的。
4. 会话标题支持就地编辑；列表每条会话右侧常驻「更多」按钮，右键或 `Shift+F10` 也能打开同一菜单，提供重命名、归档/取消归档、导出和删除。菜单支持方向键、Escape 关闭和焦点归还，通过独立按钮避免触发会话跳转。操作以选中条目的 ID 为准，无需先打开该会话，保留当前聊天和输入草稿；重命名失败保留输入，归档/删除确认明确显示目标名称。顶栏保留当前会话操作菜单，导出下载 Markdown。删除是软删除，会话和消息进入聊天回收站并可在永久删除前恢复；删除当前会话返回新对话，删除其他会话保持当前位置。
5. assistant 回答只展示真实 citations。提示按 `answerStatus` 区分：`no_basis` 显示「当前知识库中未找到足够依据。补充相关文档后可以再问一次。」，`retrieval_failed` 与 `model_refused` 分别展示对应原因；`answered` 的会话类回答允许空引用。旧记录缺少或使用未知状态时保留兼容规则：有引用则不补提示，空引用显示无依据文案；不将该历史兜底扩展到 `answered`。
6. citations 至少展示 `filename`、`pageNumber`、`content`、`vectorScore` 和 `rerankScore`。来源摘要保留在每条回答下方的可展开列表中，点击来源名称在当前聊天内打开原文。来源卡默认展示短摘录，长原文按需展开；向量分和精排分收纳在「检索详情」中，`rerankScore=null` 明确展示为「无精排分」。
7. assistant 正文中的合法 `[source:n]` 或 `[source:n,m]` 标记转换为可点击来源角标，仅当整组编号都对应本条回答的 citations 时生效；组内重复编号只展示一次，超长分组以及含无效或越界编号的标记整组保留原文。点击后展开来源列表、高亮对应条目并打开原文预览。
8. Rerank 降级只在后端返回 `rerankFallback.used` 时提示，不得由前端推测。
9. 每条 assistant 回答提供「有帮助 / 没有帮助」二选一反馈控件，当前评价使用 `aria-pressed` 表达并从 `message.feedback` 恢复。保存期间只禁用该条回答的反馈控件；成功后局部更新消息，失败保留原状态并提示，重复选择按后端覆盖语义处理。
10. 生成期间提供「停止生成」操作并中止当前 SSE。主动停止仍先按原 `clientRequestId` 对账，不能在结果未知时宣称服务端未提交；确认未提交后可保留已收到的 delta/citations 作为未落库临时内容，并恢复继续提问。服务端在生成完成后、落库前必须再次检查请求 context，避免已取消请求进入持久化事务。
11. 只有用户停留在消息区底部附近时才随 delta 自动滚动；用户主动向上查看历史后，后续 token 不得强制拉到底部。
12. user 消息提供复制和编辑操作；assistant 消息提供复制，只有最新 assistant 回答提供重新生成。所有图标按钮必须有可访问名称，复制成功和失败都要有明确反馈。
13. 编辑 user 消息时在原位置显示多行输入框，支持 `Escape` 取消、`Ctrl/Cmd+Enter` 保存并重新生成。提交期间禁用重复操作；成功后替换目标及其后的消息，失败保留编辑草稿和原会话内容。
14. 桌面正文和已有会话输入框使用居中的 800px 阅读宽度上限，新对话启动器最大宽 750px。新会话的自动检索与指定文档入口位于输入框底部，知识库卡片可选 1–5 库；已有会话保留顶部范围说明，输入区也显示当前范围。用户问题以左对齐的大字呈现，完整、流式和停止后的回答都带「知识助手」标识。发送使用带可访问名称「发送」的圆形箭头按钮，生成时替换为「停止生成」。已有会话出现提示条时输入框仍保持在会话区域底部，禁用原因通过 `aria-describedby` 关联输入框。
15. 完整、流式和停止后的 assistant 回答共用 Markdown 渲染，支持标题、列表、表格、引用、行内代码与代码块。表格和长代码在自身区域滚动；常见语言代码高亮，未知语言保留纯文本。代码块提供独立复制和失败提示，复制内容不包含围栏；整条回答复制仍保留原始 Markdown。
16. 引用角标只转换正文中的合法标记，行内代码、代码块和已有链接中的标记保留字面值。流式引用随后端 citations 到达再解析；不执行回答中的 HTML，不允许危险链接，模型图片只显示为用户主动打开的链接。
17. 原文预览在 `>= 1600px` 的桌面右侧显示为 400px 非模态面板，保留消息、输入草稿与生成状态；`<= 1599px` 时使用模态抽屉。完整、流式及停止后回答均可打开来源；切换会话或知识库时关闭旧预览，关闭后将焦点归还来源按钮。
18. 先核对文档所属知识库，再调用预览接口；仅有 `document.download` 能力时提供下载并请求 PDF 原文件。只读成员保留引用摘录与页码，显示无原文件访问权限的说明，不主动触发下载接口的 403。TXT/Markdown/DOCX 原文先去掉开头 BOM、把 `\r\n` / `\r` 统一为 `\n`，再按 citation 的 `startOffset` / `endOffset`（UTF-8 字节）换算为字符位置高亮并定位；偏移缺失、越界或切在字符中间时，退回完整摘录匹配，仍失败时去掉摘录首行（切片加入的标题路径）再匹配；都失败则保留引用摘录供对照。
    PDF 使用本地 Blob URL 和有效正整数 `pageNumber` 定位；缺失或越界页码不猜测高亮页。引用页内用完整摘录匹配 PDF.js 文本层：按 Unicode NFKC 统一全半角、连字等兼容字符，忽略排版空白、零宽空格和软连字符，不进一步删除标点、普通连字符或忽略大小写。仅唯一完整匹配时高亮，保留原始文字与完整字素（不截断连字或 emoji），不把 Go 解析器的字节偏移直接套到 PDF.js，也不剥离 PDF 摘录首句。未匹配或同页重复时提示对照上方摘录。点击「定位到引用」返回引用页，已匹配时滚到高亮；只滚动 PDF 阅读区域，不抢焦点或滚动聊天。同页切换引用不重新下载；翻页移除其他页的高亮，缩放或宽度变化后重新定位。普通文档阅读不增加引用控件。
    加载失败可局部重试，旧请求不能覆盖新来源，关闭或切换文件时释放 Blob URL；下载能力被收回后立即隐藏已加载的原文件。
19. 会话标题区提供「查找会话消息」，支持 `Ctrl/Cmd+F` 打开、不区分大小写的字面关键词查找、匹配消息计数及上一条/下一条循环定位。搜索输入框内 `Enter`/`Shift+Enter` 切换结果，输入法组合期间不切换；`Escape` 关闭并归还触发按钮焦点。匹配摘要高亮关键词，目标消息使用完整轮廓，不改变 Markdown、代码复制或草稿。切换会话清空查找状态。
20. `?messageId=` 只定位当前会话内获授权的消息；直接打开深链用 `around` 读取目标附近约 50 条，窗口两端保留完整问题/回答版本组。同会话内目标未加载时也只替换为局部窗口，等待完成后滚动并聚焦，高亮保持到取消定位。`CHAT_MESSAGE_NOT_FOUND` 局部提示，不误清空整个会话；不额外读取其他会话。会话内查找在完整小会话中本地匹配，长会话用服务端分页搜索，下一条/上一条可跨搜索结果页，输入及中文组合期间丢弃旧结果。查找或深链定位期间不自动滚到末尾；质量页的负反馈和单条知识缺口链接携带对应消息 ID。
21. 同一 user 问题后的连续 assistant 消息按回答版本展示，只显示一个版本，首次加载及重新生成成功后默认显示最新版。多个版本提供上一版、下一版与当前位置，切换时保留输入草稿，复制、反馈与来源跟随当前版本；不同问题的回答独立展示。查找和 `?messageId=` 命中历史版本时自动切到该版本，手动切换版本会退出查找和定位。后端保留完整消息记录，生成失败保留原回答与局部重试提示。
22. 新会话在首次问题保存后自动命名。发送完成或确认消息已保存时刷新会话列表，顶栏采用较新的会话数据；更新时间相同时保留当前详情，避免覆盖归档状态。消息列表刷新失败不阻止名称刷新。模型不可用时保留首问摘要；后续提问、编辑和重新生成不改变标题，用户手动命名优先。
23. 普通发送、流式握手和重新生成遇到 `429 RATE_LIMITED` 时，在输入框旁以内联 `role="alert"` 展示剩余秒数，不创建失败回答、不进入 Toast。发送问题恢复到输入框；用户继续编辑时清除旧提示。提示通过 `aria-describedby` 与输入框关联。倒计时、到期和手动重试约定与登录一致，计时只更新提示组件。
24. 流式首段立即显示，后续文本按 50ms 合并发布；结束以持久化消息替换，停止保留已收到的完整文本，切换会话清除待发布文本。历史消息不随 token 全量重渲染。会话交互状态统一重置，请求持有者在首次创建会话后的 URL 变化中保持连续。
    同一消息已渲染的 Markdown 正文仅随 `content` 或有效引用数变化重新解析；有 `onSelect` 时有效引用数为 `citations.length`，无回调时为 0。引用元数据、点击回调与 `focusedIndex` 通过独立上下文保持最新，同一正文更新引用信息或切换流式状态时仍正确更新名称、点击行为和键盘焦点。
25. `<= 1080px` 的会话侧栏使用模态抽屉：初始焦点、Tab/Shift+Tab 循环、背景隔离、Escape 关闭与焦点归还遵循 `useModalFocus`；关闭后内容 inert 且不进入辅助技术树。嵌套浮层只处理最上层 Escape，恢复宽屏时移除模态约束。
26. 普通打开会话请求最近 50 条消息，页首按完整问题/回答版本组扩展，实际可超过 50 条；首次消息挂载时立即定位到底部，不播放整段历史的平滑滚动。顶部提供「加载更早的消息」，滚到距顶部 120px 内时自动加载；追加前记录当前可见消息位置，追加后恢复阅读锚点。已加载历史不卸载，本实现是分页而非虚拟列表。
27. 历史读取失败保留现有消息并重试原方向；`CHAT_MESSAGE_CHANGED` 提示重新加载会话。失效目标的提示在继续翻页及重试时保留，不重复定位或打断分页请求。除 `CHAT_MESSAGE_NOT_FOUND` 外的 403/404 清空会话及来源并返回新对话；切换会话、刷新、重新选中目标和开始写操作使旧历史请求失效。发送、编辑、重新生成或结果未确认时暂停历史扩展，避免迟到数据覆盖写入结果。
28. 写后从已加载最早游标刷新到末尾，锚点被编辑删除时回退到最新页；主动展开过全量历史后继续使用全量刷新。跨刷新存在未确认发送、编辑或重新生成时首次全量读取以安全对账，不能用未包含旧消息的一页推断写操作未成功。导出始终由后端返回全部消息，不受当前加载页数影响。
29. 侧栏「搜索会话内容」打开模态搜索，默认查找本人所有活跃及归档会话，不受当前知识库侧栏筛选限制。250ms 防抖，关键词最多 200 字符，中文输入法组合期间不请求；结果每页 20 条，显示会话标题、归档标记、提问/回答、时间及高亮摘录。支持分页、空结果、局部错误重试与 Escape 关闭，切换条件或关闭后丢弃迟到结果。点击进入原会话并定位确切回答版本。
30. 查看局部历史时支持「加载更早的消息」「加载后续消息」和「回到最新消息」。仍有后续消息时暂停新提问及把窗口末条误当最新回答的重新生成；回到最新页后可继续提问，草稿保留。编辑旧问题仍沿用明确的后续消息删除提示；成功后末尾和游标状态随新回答更新。

### 未确认写操作的处理

发送和重新生成都是非幂等写操作，网络结果未知时的处理规则如下。**这些规则约束行为，不约束措辞**：

1. 每次首次发送生成 UUID `clientRequestId`；显式重发必须复用原 ID，不得按消息数量或文本相等推测。
2. 结果未知时持久化 pending request，跨刷新按消息的 `clientRequestId` 对账。
3. **前端必须先自动对账两次（约 2 秒和 5 秒后）**，再考虑打扰用户。自动对账期间展示的是进行中的状态，不是需要用户决策的警告。
4. 自动对账仍未发现该消息时，才提供「再检查一次」和「确认重新发送」，且必须由用户显式确认才能再次发起写操作。
5. 只有明确的业务失败（4xx，或 `CHAT_COMPLETION_FAILED`、`RERANK_FAILED`）才允许直接重试；网络中断和未分类 5xx 一律走对账路径。
6. 重新生成失败或待确认的状态必须显示在对应 assistant 消息内。若浏览器无法持久化保护状态，则不得发起写操作。
7. 重新生成成功后直接使用接口返回的 `message` 更新线程；不得因后续列表刷新失败将已成功的写操作误报为失败。
8. 模型或检索错误展示中文业务提示，不直接显示 Provider 原始错误。
9. 编辑消息同样持久化原 `clientRequestId`。响应丢失时先按该 ID 读取消息列表对账；已提交则采用服务端消息，不得使用新 ID 重复生成。
10. `RATE_LIMITED` 是服务端在写入前给出的明确拒绝，立即清理 pending 状态并按输入区限流提示处理；等待窗口后重新发送可使用新的 `clientRequestId`。

## 全局搜索页

1. 关键词、结果类型和分页分别保存在 URL 的 `q`、`type`、`page`、`pageSize` 参数。
2. 全部、知识库、文档和内容片段筛选由服务端执行；切换类型或查询时重置到第一页，刷新和前进/后退后状态不丢失。
3. 输入停止 300ms 后以 replace 模式同步 `q`，显式提交立即同步；查询、类型或分页变化时中止过期请求，并防止忽略 AbortSignal 的旧 Promise 覆盖新结果。
4. `type=all` 时结果按类型分组展示。
5. 使用服务端 `total` 展示真实总数与前后翻页，不得用当前页 items 推测各类型总数。
6. 关键词高亮只渲染服务端返回的 `highlights`，偏移量按 UTF-16 code unit 解释；不得再由前端自行做子串匹配。
7. 明确展示加载、空结果、错误和局部重试状态，并通过 `role="status"` 播报搜索状态。
8. 存在有效查询时提供「导出 CSV」，参数必须复用当前 `q` 和 `type`，不受当前分页限制；导出期间只禁用导出按钮，失败不得清空搜索结果。超过 5000 条时展示后端 `EXPORT_TOO_LARGE` 的用户消息。
9. 搜索建议来自 `GET /search/suggest`，只给标题级结果（知识库、文档），是「已经知道要找哪一个」时越过结果页的快捷方式，不是结果页的替代：内容片段只在结果页出现，否则两个视图互相抢。按 ARIA 1.2 combobox 实现——listbox 是 input 的兄弟节点，焦点全程留在输入框，当前项由 `aria-activedescendant` 指示；方向键不得移动焦点，否则用户无法继续输入。打开列表不预选任何项，刚输入完按 Enter 表示「搜我输入的内容」。建议请求失败静默处理，下面的完整搜索会报告真正的错误。建议列表刻意不加 live region：combobox 模式下读屏已经在念当前项，再播报数量会和结果页的 `role="status"` 互相打断。
10. 无结果时的建议必须与后端的匹配方式一致。`GlobalSearchRepository` 走 `LOWER(column) LIKE '%query%'`——单次小写子串匹配，不分词。因此空格、引号和 `+ - | * ~` 都是字面字符，最有用的建议是拆短或去掉符号；「换一种大小写」是错的（查询本来就不区分大小写）。建议按证据强弱排序，只有「其他类型下确实有结果」是被观察到的事实，其余都是推断；无法确定时退回通用文案，不给自信的错建议。刻意不为空结果再发一次请求做「猜你想搜」。

11. 页面明确说明“搜索名称与原文关键词”，结果采用带分隔线的连续列表，依次区分标题、所属知识库和摘要。文档结果中作为摘要返回的已知状态值使用文档页中文标签；原文片段保持原文和服务端高亮偏移，不把翻译后的状态套用原始偏移。

## 标签管理页

1. 列表支持名称筛选和移动端字段标注卡片布局。
2. 新建和编辑在共享 Dialog 中完成；失败后保留输入并展示后端 `message`。
3. 创建和更新成功后局部更新列表，不重新加载整表。
4. 删除前确认；删除失败时保留原行和确认框，并在确认框内展示后端错误。
5. 「使用量」列展示后端 `knowledgeBaseCount`；兼容旧响应缺少该字段时才显示 `—`。

7. 标题区提供新建操作，搜索和使用量表格位于下方，与全局搜索页使用一致的内容宽度和标题层级。

## 质量运营与系统诊断

1. 两页使用统一的标题、说明、刷新操作和内容宽度。质量运营将周期、知识库、引用筛选集中在独立筛选面板，概览、负反馈和知识缺口分别展示。
2. 质量运营各区域独立加载与重试；React Strict Mode 重放挂载过程后，成功响应仍须更新页面，不能永久停留在 Skeleton。
3. 系统诊断在桌面并排展示依赖状态和任务队列，Provider 与调用耗时占完整内容宽度；窄屏合并为单列。
4. 诊断只展示真实配置和调用指标；服务重启后的统计归零、未配置 Provider 和暂无耗时样本必须有明确说明。
5. 系统诊断依赖 `/auth/me` 返回的系统 `role=admin`，与知识库的 manager 角色独立。普通用户隐藏诊断导航及质量页入口；直接访问时显示权限说明，不请求诊断数据。身份加载失败可重试，切换账号立即清空旧身份与诊断内容。服务端返回 `SYSTEM_ADMIN_REQUIRED` 时清空已展示的诊断并刷新身份；服务端数据库鉴权始终是最终依据。
6. 诊断页展示当前进程的登录 / 聊天限流触发数，以及 query embedding cache hit、miss、error 和命中率；没有 hit/miss 时命中率显示“暂无数据”，不得显示 `NaN` 或伪造 0%。

### 差评与回归评测

1. 聊天中标记「没有帮助」打开原因与说明表单，支持不准确、缺少依据、答非所问、不完整、其他。
   说明最多 1000 字；保存失败保留输入并可重试，关闭未保存修改沿用统一确认与焦点恢复。
   好评直接保存并清空差评详情。不同回答的反馈仍按消息独立提交。
2. 质量页分为「反馈与缺口」「用量统计」「回归评测」，`tab`、`knowledgeBaseId` 写入 URL。
   用量统计提供统计范围（最近 7 / 30 天）与分组（按天 / 知识库 / 用户 / 模型 / 用途）；按天时展示 token 折线图（缺失日期补 0）与表格，其余分组展示带名称的表格。配置了 `MODEL_PRICING` 时显示估算成本并列出未定价模型，未配置时提示仅显示 token 数。
   负反馈展示原因和说明，提供「保存为测试问题」，预填原问题；保存后进入对应知识库的评测页。
   知识缺口四类行（含反复改写聚类的代表问题）同样提供「保存为测试问题」：打开对话框前读取该知识库已有测试问题，问题去首尾空白并折叠连续空白后相同时就地提示“该问题已在此知识库的测试集中”而不重复创建；读取失败时照常打开对话框，由服务端校验权限与每库 200 条上限。
3. 测试问题支持手工新增、编辑、删除，字段为独立问题、可选参考答案、每行一个关键词、引用要求。
   默认要求引用，每库最多 200 题，单次最多选择 20 题。保存失败保留输入；删除确认说明历史结果保留，
   成功后焦点移到相邻问题复选框，无相邻问题时回到新增按钮。
4. 批量重测独立设置名称、召回数量、精排数量、相关度阈值和是否精排，初值来自知识库配置。
   显式 0 阈值有效；全局未启用精排时提前说明，结果展示实际模型与精排状态。
5. 每次创建先按当前用户与知识库把请求编号及完整请求保存在 sessionStorage；未知结果保持表单锁定，
   刷新/重新挂载后可继续核对原编号。明确的 4xx 错误解除待确认状态；成功或列表找到相同请求时清理。
   同一请求重试不可使用新的编号或配置，旧列表响应不能覆盖刚创建的运行。
6. 页面轮询真实后台状态，失败退避，离开页面终止轮询；切页和刷新后从服务端重新加载运行。
   可取消 queued/running 运行并查看已完成题目。切换候选运行或基准时，迟到详情不得覆盖当前选择。
7. 历史入口提供最近 50 次运行，可选择一次运行和对比基准。只比较同一题目 id 且问题、参考答案、
   关键词与引用要求相同的快照；规则变化的题目不加入统计。
   分别显示规则通过数、含引用回答数、调用失败、耗时与配置（含运行创建时的回答配置快照与实际回答模型），
   选择基准后列出两次运行在检索配置和回答配置上的差异项，每题可展开 Markdown 答案和真实来源链接。
8. 规则通过仅表示满足显式关键词/引用要求，参考答案供人工核对。无自动规则显示「待人工核对」，
   调用失败显示独立错误，不计作规则未通过；中断、取消中的未执行题目不得伪造答案。

## 系统管理

`/admin/users`（`pages/Admin/UsersPage.tsx`，懒加载分包）是系统管理员管理账号的页面，导航入口与系统诊断并列在「系统」分组。

1. **准入**：与诊断页同源，依赖 `/auth/me` 返回的 `role=admin`。普通用户看不到导航入口，直接访问 URL 时 `Navigate` 回首页，不发起 `/admin/users` 请求；身份加载失败同样回首页。服务端 `RequireSystemAdmin` 仍是最终边界。
2. **列表**：表格列为用户名、显示名、角色、状态、最后登录、操作。筛选条为用户名/显示名关键词、状态（全部/启用/已禁用）、角色（全部/管理员/普通用户），任一筛选变化都回到第 1 页；关键词、状态、角色以 `q`、`status`、`role` 原样传给 `GET /admin/users`，空值不传。关键词按 250ms 防抖，清空/Enter 立即提交，输入法组合期间不请求。只有最新读取能更新结果、总数、加载和错误；写后刷新读取当前筛选及分页，卸载后旧请求失效。
3. **分页**：使用通用 `Pagination` 组件，`page` / `pageSize` 来自服务端响应，默认每页 20，可选 10/20/50/100；总数显示为「共 N 条」。不再一次拉取 100 条。
4. **创建对话框**：字段为用户名（必填）、显示名（可选，留空用用户名）、初始密码（可选）。客户端先校验：用户名非空且匹配 `^[A-Za-z0-9._@-]{3,64}$`；显示名不超过 `account.maxDisplayNameLength`；指定密码时按 `GET /system/capabilities` 的 `account.minPasswordLength` / `account.maxPasswordBytes` 校验，错误以字段级 `Field` 错误展示。服务端 `USERNAME_EXISTS`、`VALIDATION_ERROR` 在对话框内以 `role=alert` 展示，不关闭对话框。
5. **编辑对话框**：修改显示名和状态，调用 `PUT /admin/users/:id`。目标是当前登录管理员时状态控件禁用并说明原因。
6. **确认对话框**：禁用、撤销管理员、重置密码三个破坏性操作先经 `ConfirmDialog` 确认，说明后果（禁用会让已登录会话在下一次请求失效；重置密码使旧密码立即失效且新密码只显示一次）。服务端拒绝（如 `LAST_ADMIN_REQUIRED`、`ADMIN_SELF_MUTATION`）时错误留在确认框内，不关闭。启用和授予管理员是可逆操作，直接执行。
7. **一次性密码**：创建和重置密码的结果在独立对话框显示一次，提供「复制密码」（复制成功有 `role=status` 提示）；关闭后密码不再出现在页面任何位置。
8. **自身行**：当前登录管理员的行标注「（我）」，不显示禁用、撤销管理员、重置密码按钮——服务端会以 `ADMIN_SELF_MUTATION` 拒绝，页面不提供会失败的入口；编辑显示名仍可用。
9. **活动时间线**：管理操作以 `resourceType=user`、`action=admin.user.*` 出现在首页时间线，文案分别为「创建了用户」「更新了用户」「重置了用户密码」「调整了用户角色」，链接回 `/admin/users`。

## 全局反馈与可访问性

### 异步查询与保存

- 聊天、文档、质量页共享知识库选项查询（page=1、pageSize=100、updatedAt_desc）。同账号同参数共享在途请求；数据 60 秒内有效，无观察者后保留 5 分钟，过期挂载或手动刷新重新读取，不因窗口聚焦自动刷新。网络/5xx 最多重试一次，401/403/429 不自动重试，写入不自动重试。
- 知识库创建、改名、删除、恢复、永久清理及成员权限写入成功后失效选项查询；认证变化清除旧账号缓存，忽略迟到结果。普通刷新保留已有选项并展示失败提示，401/403 清空旧选项并保留可重试错误。URL 的知识库范围不因选项第一页缺项而自动改成“全部”，避免扩大筛选范围；已不可用的选项不会提供旧权限操作，后端始终逐次鉴权。
- 路由渲染异常显示中文恢复界面，可重试显示、刷新或返回首页；lazy chunk 失败需刷新重新加载，并提示未保存输入会丢失。Markdown/PDF 的局部异常在原位置恢复，保留聊天与输入区。边界不替代 API 和异步事件错误处理。

- 知识库概览切换统计周期时清空旧值并显示加载状态，迟到的成功或失败响应不能覆盖当前周期。
  概览和设置切换知识库时重置旧库的页面状态，文档摘要读取失败不同时展示“还没有文档”。
- 检索配置保存期间锁定相关字段并防止重复提交；失败保留草稿，重置恢复已保存配置并清除错误。
  检索测试分别展示未检索、加载、失败和无结果，切库后清理旧问题及结果。
- 成员搜索显示加载、结果数、无匹配与失败反馈；修改关键词立即使旧结果失效，避免添加上一轮搜索的人。
  可见性选择必须和文字标签关联。诊断刷新显示进度并禁用重复刷新，等待期间保留已有诊断数据。
- 弹窗指定的初始焦点若因加载被禁用或隐藏，应聚焦第一个可用控件；Tab 顺序跳过负 tabindex、
  隐藏输入、CSS 隐藏及惰性区域。控件恢复可用后不抢走用户已移动的焦点。

### 通用规范

1. Button、IconButton、Field、Badge、Table、Pagination、Drawer、Popover、EmptyState、ErrorState、LoadingSkeleton、Dialog 和 Toast 使用统一语义样式，全部定义在 `src/styles/primitives.css`。
2. 图标按钮必须同时提供 `aria-label` 与 tooltip，不使用字符或英文占位图标。
3. 搜索类输入框的移动键盘提示由 `SearchInput` 统一给默认值，不在每个调用点重复：`enterKeyHint="search"`（手机上显示搜索键而不是换行键），以及 `autoCapitalize` / `autoCorrect` / `autoComplete` 全关——自动大写和纠错会和标识符、文件名打架，浏览器的自动填充下拉还会盖住建议列表。默认值写在展开之前，调用点仍可覆盖。
4. 表单字段的提示和错误必须通过 `aria-describedby` 关联到控件；错误同时设置 `aria-invalid` 并使用 `role="alert"` 播报。
5. Dialog 与 Drawer 支持 Escape、焦点约束、背景滚动锁定和焦点恢复，并支持嵌套。
   用户管理和诊断延迟表的单元格保留桌面表头语义，并通过 `data-label` 提供窄屏卡片布局的字段名称。
6. 所有交互控件保留明显 `:focus-visible`；关键移动端触控目标不低于 44px。触控尺寸只有一个归口：`styles/touch.css`，断点是 `@media (max-width: 980px)`，用宽度而不是 `(pointer: coarse)`——二合一笔记本接触控屏时也报 coarse，但用户手上是触摸板。装文字的控件只写 `min-height`，不写 `height`，内容本来就更高的控件不能被压小；方形图标按钮是例外，两个方向都写，点击区域要和看得见的圆形一致。页面样式表不得再自行定义触控尺寸；`touch.css` 必须最后引入，靠顺序而不是 `!important` 取胜。悬停才显示的行内操作在这个断点必须常驻可见，没有指针就没有悬停。
7. 危险操作统一使用 `ConfirmDialog`；失败保留在确认框内，成功通过全局 Toast 通知，不使用原生 `window.confirm`。
8. 支持 `prefers-reduced-motion`；成功、警告和危险状态不能只依赖颜色表达。
9. 知识库、分类、标签等编辑表单以及待导入文件清单存在未保存内容时，取消、Escape 或遮罩关闭必须先确认；刷新或关闭标签页时使用 `beforeunload` 保护。
10. 全局 Toast 在 Dialog 或 Drawer 打开期间仍须可见并可被辅助技术播报，但不得成为可交互的焦点目标。
11. 整个应用只有一个 `<main>` landmark，由 `AppShell` 拥有。
12. 一个页面同时只能有一个 polite live region 在描述同一件事。多个 polite 区域会互相打断，这正是「克制的播报」要排除的情况；测试里 `getByRole('status')` 在存在多个时直接抛错，这个抛错本身就是断言。live region 必须常驻在 DOM 里、只改内容：和文字一起挂载的区域播报不可靠。流式回答的阶段播报见 `useStreamAnnouncement`——检索、生成、已停止、完成各说一次，失败不说，因为线程里的失败提示是 `role="alert"`（assertive，自己会播报），再说一遍就是重复。
13. 焦点归还是每一条关闭路径的义务，不是可选项。视觉上看不出焦点丢失，所以每条路径都要有测试锁住：
    - Dialog、Drawer 统一走 `useModalFocus`（堆叠、焦点约束、背景 `inert` / `aria-hidden`、Escape、Tab 循环）。触发元素已经不存在时退到 `[data-modal-focus-fallback]`，该标记必须至少有一个在桌面端也渲染的控件上。
    - portal 浮层（Popover、OverflowMenu）用 Tab 关闭时必须 `preventDefault` 再手动把焦点放回触发器。不能放默认行为走：浏览器计算 Tab 目标时 React 还没卸载面板，焦点会进入即将消失的面板，最后落到 `body`。代价是多按一次 Tab，换来的是永不丢焦点。
    - 浮层打开时必须主动把焦点移进面板。portal 挂在 `body` 末尾，Tab 会跳过它，不移进去等于键盘用户根本到不了，Escape 也收不到 keydown。
    - 点击外部关闭属于「用户已经去了别处」，不得把焦点抢回触发器；只有键盘关闭才归还。
    - 就地编辑（InlineEdit）进入编辑要显式 `focus()`，不能只靠 `select()`；保存、取消、Escape 三条退出路径都要回到触发按钮。
    - 列表行删除后焦点落到相邻行的同一个控件（末行则落到前一行），用 `useRowFocusAfterRemoval`：相邻行在删除**开始**时选定（那时行还在），焦点在 effect 里移动（对话框在自己的 cleanup 里归还焦点，React 先跑完 cleanup 再跑 effect）。只剩一行时交给上面的 fallback。

## 样式约束

~~~text
src/styles/
  tokens.css        设计令牌，唯一允许出现颜色和尺寸字面量的地方，含深色模式
  reset.css
  primitives.css    跨页复用的组件样式
  app-shell.css     导航、顶栏、命令面板
  pages/*.css       每个页面一个文件
  touch.css         移动端触控尺寸，必须最后引入
~~~

1. `pages/*.css` 之间不得互相引用选择器；任何跨页复用必须提升到 `primitives.css`。
2. 页面样式表不得重新定义 `primitives.css` 中的 `.ui-*` 选择器。
3. 层级由 1px 边框表达，投影只用于浮层（Dialog、Drawer、Popover、Toast、命令面板）。
4. 强调色只有一个，状态色只用于表达状态，不用于装饰；知识库封面可使用独立的柔和配色。配色、阴影、字号和公共尺寸在 tokens.css 集中维护；登录页使用固定的深绿品牌展示面，明暗主题都必须保持文本对比度。
5. 字号只使用 tokens 中的六级尺度。
6. 竖向视口尺寸一律用 `dvh`，不用裸 `vh`：移动端地址栏和软键盘会压缩可视高度，`vh` 不跟着变，结果是内容被挤而留白不动。横向的 `vw` 不受这两者影响，不在此列。`styles/viewport-units.test.ts` 守住这条。

## API 与代码约束

1. token 保存在 token store；API 请求统一注入 `Authorization: Bearer <token>`。
2. 401 时清理 token 并跳转登录页；错误反馈优先使用后端 `message`。
3. API 客户端保留 `status`、`code` 和解析后的 `retryAfterSeconds`。429 文案统一由客户端格式化，优先 HTTP `Retry-After`，再读 `details.retryAfter`，同时覆盖 fetch、上传 XHR 与 SSE 建连前错误。
4. 页面级筛选优先写入 URL；本地显示偏好写入 localStorage；可过期请求通过 `AbortSignal` 取消。
5. 路由页面使用 `React.lazy` 分包；`App.tsx` 只承载 Outlet，不堆叠页面实现。新增或删除路由页面时必须同步更新 `scripts/verify-route-chunks.mjs`。
6. `resources.ts` 保持兼容导出；API 字段使用 camelCase，不伪造文档状态、检索分数、Rerank 状态或 citations。
7. 时间、字节、数字和分数的格式化统一使用 `src/utils/format.ts`，不在页面内重复实现。
8. 并发写操作使用 `useEntityMutation` 按实体 id 跟踪，禁止引入页面级互斥锁。

已有会话的发送、编辑或重新生成收到 403/404 时，清空消息、未确认请求、来源预览与该库的缓存选项，回到 `/chat` 并提示“会话已不可访问，可能已删除或访问权限发生变化。”，刷新可访问知识库。失效选项不能依赖刷新成功才移除；普通生成故障与 429 保留原恢复行为。服务器仍逐请求鉴权；本次不增加跨客户端撤权推送。


## 收藏、模板与对话分支

- 回答工具栏可收藏当前显示的确切回答版本；备注可选，最多 4000 字。重复保存更新备注，取消收藏不改消息；未保存关闭需确认，失败保留输入。侧栏「收藏与笔记」支持搜索、分页、编辑/取消以及跳转原消息；旧版本使用现有历史窗口与版本定位。返回 403/404 时清理失效会话和来源，不继续展示撤权数据。
- 「从此回答创建分支」显示截断位置与可选标题。创建成功后由用户选择打开新分支或留在当前会话；重试复用同一个请求 UUID。复制完成前禁止重复提交，历史加载/写入锁期间禁用入口。新分支顶栏可查看来源会话；来源永久删除后不展示空链接。
- 输入区「提问模板」打开个人模板库，支持创建、编辑、删除、搜索和分页；新建可从当前草稿开始。正文支持 `{{变量名}}`，重复变量只填一次，填值每项最多 1000 字，填入后正文最多 12000 字。插入追加在原草稿后，不自动发送。替换只执行一次，变量值里的括号是普通内容；空值、非法变量和超长内容有明确反馈。

## 文件夹、ZIP 与表格资料

- 导入对话框提供「选择文件夹」和 ZIP 选择/拖放。ZIP 库按需加载，先在浏览器展开为普通文件，再复用单文件上传、查重、替换和失败重试。选择文件夹使用浏览器 `webkitdirectory` 能力；清单显示相对路径，相同名称但不同目录不会在前端合并。来源路径作为 multipart `sourcePath` 提交并在文档详情展示。
- 单批最多 200 文件、展开总大小 200 MiB，单 ZIP 最多 100 MiB / 1000 目录项。路径穿越、绝对路径、符号链接、加密、CRC 或展开大小不符均拒绝；只接受 Store/Deflate，不展开嵌套 ZIP。混入不支持或超过单文件限制的条目时明确列出跳过原因。ZIP 实际解压字节也受限制；关闭/卸载时中止准备，迟到结果不进入队列。
- 文档详情「版本对比」选择同链两个版本并展示新增/删除行及行号；切换选择时清除旧结果并取消旧请求。不具备历史版本、未完成处理、空文本、解析失败或超过上限时显示对应说明。对比窗口位于详情抽屉上方，复用现有对话框焦点和关闭行为。
- 每个 XLSX/CSV 待导入文件可打开「表格导入设置」：按需勾选工作表，预览原始记录，填写物理表头行（0 自动），勾选原列号。至少选择一表一列，提供恢复自动设置；取消预览会中止读取。修改设置产生新请求 ID，上传中或结果未知时不可修改。
- XLSX / CSV 以表头标签加数据记录的文本形式阅读；默认首个非空记录为表头，自定义导入则复用保存的设置，详情展示所选表/行/列。保留工作表名与原行号，界面说明公式只显示已保存结果；CSV 行号是包含换行字段在内的物理行范围。空表的建议是补充数据/保存公式结果，不显示 OCR 建议。
- 引用卡片和来源面板显示「库存 · 第 5 行」或「第 3–4 行」。来源预览按工作表、行起止和表头行匹配 `tableRows`，再按响应 UTF-8 区间高亮整条记录。不同工作表的相同内容不会误高亮；没有对应行或大文件无法预览时保留摘录和来源标签。表格不提供公式重算、筛选汇总或统计图表功能。

## 多库聊天（2026-09-29）

新对话默认自动检索，输入框无需选择库即可使用；空态说明每轮匹配可访问库，提供“自动检索全部可访问知识库”按钮。知识库卡片可多选 1–5 个以指定范围，再次点击取消；全部取消或点击自动按钮恢复自动模式，已输入的问题保留。URL 仅保存手动选择。首问才创建会话，自动创建不发送隐含的首个库 ID。自动模式每轮来源可变化，手动范围创建后固定。单库侧栏下拉仍用于会话过滤和发起单库草稿，范围包含该库的跨库会话也会出现；手动列表标注库数量，顶栏显示库名；自动列表与顶栏明确标注自动检索，不把历史依赖集合显示为本轮范围。新建对话始终回到默认自动模式。

手动草稿显示已选数量及范围限制，自动草稿说明不同问题可使用不同库。自动会话允许打开本轮新出现库的引用，不依赖会话范围元数据先刷新。引用卡片和原文预览显示所属库名，预览与下载能力按引用自身的库判断；旧单库引用没有库 ID 时回退会话首选库。已有会话发送/编辑/重生成遇到 403/404，清空整段历史、来源及未确认操作，移除涉及范围的缓存选项并重新加载。草稿创建失败也要结束发送状态并提示，不能永久停在发送中。
