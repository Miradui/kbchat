# 前端综合优化设计

- 日期：2026-07-10
- 状态：已获用户确认
- 适用项目：RAG 智能知识库
- 设计路线：轻量设计系统 + 纵向切片渐进改造

## 1. 背景

当前项目已经具备 React/Vite 前端及较完整的后端 API。前端覆盖登录、首页、知识库、文档、聊天、搜索和标签等功能，但存在以下主要问题：

1. 页面和样式文件过大，`KnowledgeBaseListPage.tsx`、`styles.css` 等文件职责过多。
2. 视觉、图标、间距、反馈和响应式行为缺少统一规范。
3. 分类树在多个无关页面中出现，应用外壳的信息层级不够清晰。
4. 加载、局部操作、错误、空状态和成功反馈不一致。
5. 缺少前端自动化测试设施，重构和交互优化的回归风险较高。
6. 部分后端新增字段与前端类型可能尚未完全同步，例如 Rerank fallback 和文档任务进度信息。

本设计在保留现有业务能力的基础上，对全部现有页面做综合优化。优化包括视觉、交互、响应式、可访问性、代码结构、性能和测试，不采用一次性重写。

## 2. 已确认的设计决策

1. 所有现有页面同等纳入优化范围。
2. 采用现代企业后台视觉方向。
3. 桌面端优先，同时保证 375px 手机端可完成核心操作且无整页横向溢出。
4. 允许增加最小前端依赖：`lucide-react`、Vitest、React Testing Library、`@testing-library/user-event` 和 jsdom。
5. 不引入 Ant Design 等大型 UI 框架。
6. 允许增加轻量后端接口、查询参数或响应字段，但不新增数据库 migration。
7. 采用“轻量设计系统 + 纵向切片渐进改造”，不进行完整前端重写。
8. 保留现有路由和 API 兼容性；后端增量应尽量保持向后兼容。
9. 当前工作区已有未提交改动，实施时必须保留并在其基础上整合，不得回退或覆盖。

## 3. 目标

### 3.1 产品目标

- 提升知识库、文档和聊天核心流程的清晰度、操作效率与可追溯性。
- 统一所有页面的信息层级与交互反馈。
- 保证 citations 完整、可追溯，并明确展示 Rerank 降级状态。
- 让桌面办公场景高效，同时让移动端可以完成核心任务。

### 3.2 工程目标

- 建立轻量设计令牌和可复用基础组件。
- 将超大页面和全局样式按职责渐进拆分。
- 增加路由级代码分包和请求竞态控制。
- 建立前端自动化测试基线。
- 公共 API 或 RAG 行为发生变化时同步文档。

## 4. 非目标

本轮不包含：

- 深色模式。
- SSO、复杂 RBAC、审计日志或多租户。
- 对象存储或 docx 解析。
- 新的数据库字段或 migration。
- 改变 Embedding、向量召回、Rerank、Prompt 或 citation 的后端语义。
- 营销首页、大面积 Hero 或纯装饰动画。
- 完整替换现有前端技术栈。

## 5. 视觉系统

### 5.1 视觉基调

采用克制、清晰的现代企业后台风格：

- 页面背景：`#F6F8FB`。
- 内容表面：`#FFFFFF`。
- 主文字：`#0F172A`。
- 次级文字：`#475569`。
- 主色：`#2563EB`，悬停状态使用更深色阶。
- 边框：浅灰蓝语义色阶。
- 成功、警告、危险使用独立语义色，并同时使用图标或文字，不仅依赖颜色。
- 圆角以 8px 和 12px 为主。
- 阴影主要用于抽屉、对话框和悬浮层；普通卡片主要依靠边框与背景层级。
- 使用系统中文字体栈，不依赖在线字体资源。

### 5.2 设计令牌

建立以下语义令牌：

- 背景、表面、悬浮表面和边框。
- 主文字、次级文字、弱化文字和反色文字。
- 主色及 hover、active、soft 状态。
- success、warning、danger 及各自 soft 状态。
- 4/8px 间距阶梯。
- 8px/12px 圆角。
- 150–240ms 交互动效与统一 easing。
- focus ring、scrim 和 elevation。

组件和页面使用语义令牌，不在 JSX 中散布硬编码颜色。

### 5.3 基础组件

建立并复用：

- `Button`：primary、secondary、ghost、danger、link。
- `IconButton`：统一尺寸、状态、tooltip 和无障碍标签。
- `Input`、`Select`、`Textarea`：统一标签、帮助文字和错误状态。
- `Badge`、`StatusBadge`：映射后端真实状态。
- `PageHeader`、`Toolbar`、`Panel`、`StatCard`。
- `EmptyState`、`ErrorState`、`LoadingSkeleton`。
- `Dialog`、`Drawer`、`Toast`。
- `Pagination`。

图标统一使用 `lucide-react`，替换字符图标和英文占位文字。桌面端交互控件通常不低于 40px；移动端关键触控目标不低于 44px。

## 6. 应用外壳与信息架构

### 6.1 全局导航

左侧主导航包含：

- 首页。
- 知识库。
- 文档管理。
- 问答管理。
- 全局搜索。
- 标签管理。

删除当前无法使用且不属于 MVP 的“权限管理”占位项。

### 6.2 顶部工具栏

顶部工具栏统一承载：

- 当前页面上下文或面包屑。
- 全局搜索入口。
- 当前用户菜单和退出登录。

各页面不再自行放置位置不一致的退出按钮。

### 6.3 内容区

- 普通管理页面使用统一内容宽度和页面边距。
- 表格、知识库工作台和聊天页面可以使用更宽布局。
- 页面标题、说明、主要操作和次要操作保持固定层级。
- 知识库分类树只出现在知识库工作台上下文中，不在聊天、文档和标签页面重复显示。

## 7. 响应式与可访问性

### 7.1 响应式断点

- `>= 1280px`：完整侧栏和宽内容区。
- `981–1279px`：紧凑侧栏，减少非必要文字。
- `<= 980px`：侧栏改为可打开的导航抽屉。
- `<= 680px`：16px 页面边距；次要操作进入更多菜单；复杂表格转为字段标注卡片或分组行；详情抽屉变为全屏面板。

任何断点都不得出现整页横向滚动。局部代码、预览或数据区域如确有必要，可在明确边界内独立滚动。

### 7.2 可访问性

- 正文颜色对比度至少 4.5:1。
- 所有交互元素保留明显的键盘焦点环。
- 图标按钮必须提供 `aria-label` 和 tooltip。
- 表单使用可见标签，错误信息与字段关联。
- 对话框支持 Escape 关闭、焦点约束和关闭后的焦点恢复。
- 导航、分类树、表格操作和聊天输入可通过键盘完成。
- 支持 `prefers-reduced-motion`，关闭非必要动画。

## 8. 页面设计

### 8.1 登录

- 桌面端为简洁产品说明和登录卡片，手机端只显示登录卡片。
- 用户名和密码使用始终可见的标签。
- 密码框提供显示/隐藏操作。
- 登录失败显示在表单附近，并将焦点转移至错误摘要。
- 提交期间禁止重复提交。
- 登录成功继续跳转 `/home`。
- 界面不展示默认账号密码。

### 8.2 首页

首页定位为工作概览：

- 快速入口：新建知识库、导入文档、开始问答。
- 统计：知识库总数、文档总数、处理中/失败文档和活跃会话。
- 内容：最近知识库、最近会话、文档处理动态和失败任务。
- 优先并行组合现有接口；只有请求数量或性能确有问题时才新增只读聚合接口。
- 单个区域失败不阻塞其他区域。

### 8.3 知识库工作台

采用上下文分类侧栏和主内容区：

- 分类树提供分类计数和未分类入口。
- 分类的新建、重命名、移动和删除放入节点菜单。
- 移动端分类树放入筛选抽屉。
- 主内容提供搜索、分类、可见性、排序和表格/卡片视图切换。
- 收藏、最近访问和全部知识库是独立范围筛选。
- 勾选项目后才显示批量操作栏。
- 新建和编辑知识库使用侧边抽屉。
- 删除进入回收站；永久删除保留在回收站界面。

### 8.4 知识库详情

保留 `/knowledge-bases/:id`，内容重组为：

- 概览：文档、会话、成员和检索配置摘要。
- 检索设置：`vectorTopN`、`rerankTopK`、阈值和 Rerank 开关。
- 检索调试：Vector、Rerank、Final 三阶段和 fallback 信息。
- 成员管理：搜索、添加、调整角色和移除。

配置编辑采用显式编辑、保存和取消。危险操作独立分区。文档管理和开始问答作为主要操作。

### 8.5 文档管理

全局文档页和知识库内文档页共享列表、筛选、上传、状态和详情组件：

- 筛选：关键词、知识库、状态、文件类型和排序。
- 当前条件显示为可清除的筛选标签。
- 桌面端表格，手机端信息卡片。
- 上传明确支持 txt、md、pdf，并展示逐文件真实状态。
- 状态展示后端实际返回的 stage、progress、retryCount、maxRetries、nextRetryAt 和 errorMessage。
- 只有存在活跃任务时轮询；页面隐藏时降低或暂停轮询。
- 详情抽屉包含基础信息、处理状态、预览、chunks、下载、重新处理和删除。
- 桌面端使用右侧抽屉，移动端使用全屏面板。

### 8.6 问答入口

`/chat` 提供：

- 最近会话。
- 按知识库开始。
- 已归档会话入口。

已有会话时进入最近会话，没有时创建新会话。创建期间防止重复操作。

### 8.7 聊天页面

桌面端采用会话侧栏、消息主区域和引用面板：

- 会话支持搜索、新建、重命名、归档和删除。
- 用户消息和 Assistant 消息具有清晰但克制的层级。
- 保留模型内容换行，不将模型内容作为不可信 HTML 注入。
- 发送中只显示等待状态，不伪造回答。
- 发送失败保留用户问题并提供重试。
- 重新生成追加新的 Assistant 消息，不静默覆盖历史。
- citations 使用后端顺序，以 `[1]`、`[2]` 编号，展示文件名、页码、内容、Vector Score 和 Rerank Score。
- `rerankFallback.used=true` 时显示降级提示。
- 无引用时显示“当前知识库中未找到足够依据。”
- 引用只来自后端返回的最终引用集合，前端不自行生成或重排。

中等宽度下引用变为可开关侧栏；手机端会话和引用使用全屏抽屉。

### 8.8 消息输入

- 支持多行。
- Enter 发送，Shift+Enter 换行。
- 空内容和请求期间禁止发送。
- 显示当前知识库上下文。
- 输入区保持可见，为消息列表预留空间。
- 请求失败后保留草稿和问题上下文。

### 8.9 全局搜索

- 查询写入 `/search?q=...`。
- 支持全部、知识库、文档和内容片段过滤。
- 结果显示类型、所属知识库、文件名和摘要。
- 点击结果进入知识库或文档上下文。
- 输入短防抖并取消过期请求，旧结果不能覆盖新结果。
- 空查询、无结果和加载失败使用不同状态。
- 顶部搜索统一跳转该页面。

### 8.10 标签管理

- 页面包含搜索、新建和标签列表。
- 新建/编辑使用小型对话框。
- 删除前说明被引用时后端可能拒绝。
- 成功时精确更新对应数据；失败时保留输入并就近展示错误。

## 9. 全局反馈

- Skeleton：首次加载且暂无内容。
- 局部加载：刷新、收藏和单行操作只影响对应区域。
- Toast：创建、保存、上传、移动和归档等成功反馈。
- Inline Error：字段校验和局部可恢复错误。
- Error State：整个区域加载失败并提供重试。
- Empty State：解释为空原因并给出下一步操作。
- Confirm Dialog：删除、永久删除和清空回收站。
- 优先展示后端 `message`；未知错误使用统一兜底文案。
- 401 继续统一清理 token 并跳转登录页。

## 10. 前端代码架构

目标结构：

```text
src/
├── api/
│   ├── client.ts
│   ├── auth.ts
│   ├── knowledgeBases.ts
│   ├── documents.ts
│   ├── chat.ts
│   ├── search.ts
│   └── resources.ts
├── components/
│   ├── ui/
│   ├── feedback/
│   └── navigation/
├── hooks/
├── layouts/
├── pages/
├── styles/
│   ├── tokens.css
│   ├── base.css
│   ├── components.css
│   ├── layouts.css
│   └── pages/
├── types/
└── utils/
```

约束：

- 页面负责页面编排、数据加载和主要状态。
- 页面专用组件保留在页面目录；跨页面复用组件才进入 `components`。
- `resources.ts` 保留兼容导出入口。
- 类型按领域渐进拆分，不复制同一 API 类型。
- 不增加全局状态管理框架。
- 页面筛选、排序和分页尽量写入 URL。
- API 请求支持 `AbortSignal`。
- 远程数据通过页面或领域 hooks 管理。
- 路由页面使用 `React.lazy` 分包。

## 11. 轻量后端配合

优先复用现有接口。允许的增量仅包括：

- 补齐 `rerankFallback`、文档处理阶段/进度/重试信息和会话归档信息等前后端类型不一致。
- 首页确有性能问题时增加当前用户范围内的只读聚合接口。
- 为会话或文档列表增加必要查询参数或轻量响应字段。

所有变更必须：

- 遵循 `handler -> service -> repository`。
- 使用 GORM。
- 保持知识库 owner/member 权限和 owner_id 范围校验。
- 不新增数据库 migration。
- 不改变 RAG、Rerank 和 citation 语义。
- 同步更新 API、类型和交接文档。

## 12. 测试策略

采用 Vitest、React Testing Library、`@testing-library/user-event` 和 jsdom，并按测试先行实施。

### 12.1 基础组件

覆盖：

- Button 和 IconButton 状态。
- Dialog 的 Escape、焦点和危险操作。
- Toast、空状态、错误状态和分页。
- StatusBadge 对真实后端状态的映射。

### 12.2 页面行为

覆盖：

- 未登录跳转。
- 登录失败展示后端错误。
- 知识库筛选、视图切换和批量操作。
- 文档活跃任务轮询与终止条件。
- 搜索请求竞态。
- 聊天发送、失败重试、重新生成和 citations。
- Rerank fallback 和无引用状态。
- 标签创建、编辑和删除失败时保留输入。

### 12.3 后端测试

如增加或调整接口，补充服务层权限、所有权和 Handler 请求/响应测试，并保持 `go test ./...` 通过。

## 13. 性能与质量目标

- 路由级代码分包，避免全部页面进入首屏 bundle。
- 不引入大型 UI 框架。
- 活跃任务才轮询，页面隐藏时减少无效请求。
- 搜索防抖并取消过期请求。
- 大列表保持后端分页。
- Skeleton 和异步内容预留空间，降低布局跳动。
- 无 React key 警告、未处理 Promise 或控制台错误。

## 14. 实施阶段

1. 基线与测试设施：固化构建结果，安装最小依赖，建立测试环境。
2. 设计系统与应用外壳：令牌、基础组件、导航和响应式框架。
3. 管理页面切片：登录、首页、搜索、标签、知识库和文档。
4. 聊天切片：会话、消息、输入、引用和降级状态。
5. 轻量后端补齐：只处理实施确认的接口缺口，不新增 migration。
6. 完整回归：自动化测试、构建、真实后端联调、响应式和键盘检查。

每个切片完成后都必须保持构建和已有测试通过，不把全部风险推迟到最后。

## 16. 风险与控制

### 16.1 未提交改动冲突

风险：聊天、知识库详情、样式和类型已有未提交修改。

控制：开始每个切片前检查 diff；只做增量编辑；不 reset、不 checkout、不覆盖他人修改；先补测试再重构。

### 16.2 全页面范围过大

风险：一次性修改导致回归范围过大。

控制：按纵向切片实施；每个切片独立验证；设计系统先行但不一次性重写所有组件。

### 16.3 设计系统过度抽象

风险：为未来假设建立复杂组件 API。

控制：只有至少两个真实页面需要时才提升为跨页面组件；页面专用组件留在页面目录。

### 16.4 前后端契约漂移

风险：前端根据文档或假设使用不存在的字段。

控制：以实际 DTO 和 API 响应为准；同步更新 TypeScript 类型、后端测试和 API 文档。

### 16.5 移动端表格可用性
